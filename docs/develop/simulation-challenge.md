# 模拟室准备到领奖的完整挑战流程

`SimulationChallengeRun` 接收已有的已验证关卡与冻结计划，在同一运行 ID、控制句柄和总活动预算内串联卡片 / 电量准备、详情推进 / 选队和单战 / 领奖返回。复用原有执行器、画面区域和输入动作；具体规则见[准备](simulation-preparation.md)、[详情与选队](simulation-entry.md)和[单战](simulation-battle.md)。

构造时先验证关卡属于计划且 `selection_verified=true`、默认等级、恢复策略、完整编队和脚本名称，再冻结已编译脚本及全部下游资源。当前[传送与选关流程](simulation-approach.md)只产生未验证回执，不能构造本流程；没有增加证明生产者、人工覆盖开关或公开游戏输入入口。

卡片、恢复电量、选队、出战、结算及战斗资源均在首个卡片输入之前完整校验，并冻结清单哈希。运行、继续和阶段切换复验冻结资源；后续脚本导入不改变已经编译的本次指令。实际游戏的界面阶段取得唯一原生槽位的前台键鼠 / CPU 会话，战斗和领奖交接沿用单战执行器；隔离模式拒绝手柄和 DirectML 配置。

每次阶段交接先完成子流程收尾和终态保存，再保存父阶段，随后才允许后继输入。准备返回实际电量不足时明确结束为 `InsufficientCharge`，保留实际数量、电量及恢复结果，不进入详情推进或出战。成功证明须包含本次运行身份、冻结计划和实际领奖后电量；它仍不直接登记计划次数或每日成功。

暂停不重置活动预算，继续重新装载当前资源。即使子流程已经返回，父流程终态保存期间才收到暂停，也会撤销旧准备 / 到达 / 领奖证明，重新读帧；已经提交的卡片保存、电量兑换、出战及领奖不重复执行。停止优先，保存失败、超时、错误返回或输入未释放不能产生成功证明。外层在构造冻结资源后重新计算自身剩余预算，所有执行期校验、装载、保存与收尾均计入预算。

后续已接入[体力循环与次数登记核心](charge-run.md)，通过实际挑战终态及独立执行 ID 登记，不直接修改用户配置。本轮保留协议 v46、导入预览 v19、资源 schema 与正式可用标记。关卡选中态素材和证明生产者、传送到挑战的最终连接、完整体力自动循环和跨运行登记、真实游戏与设备交接及全部实机验收继续保留。

```powershell
cargo test --locked --manifest-path zzz-od-test/test/zzz_auto/rust/Cargo.toml --target-dir target/validation-restore-charge --test simulation_challenge -- --test-threads=1
```

回放以明确构造的已验证关卡作为测试前置，通过真实 Maa SDK 的隔离控制器和已有恢复 / 奖励留档、组合卡片 / 详情 / 出战帧推进；没有连接游戏、修改用户配置或增加计划次数。恢复前后的电量、卡片数量和领奖后电量分别核对，不将准备结果的 `selection_verified=false` 改为关卡选中证明。

2026 年 10 月 27 日新增 21 项回放通过，覆盖完整默认方案、固定卡片和恢复串联、库存不足、连续暂停及会话重建、父终态暂停后的新帧复验、阶段保存、资源变化、超时与保存失败、撤退及错误返回。连同相邻 24 项核心与 3 项原执行器终态回归，按唯一用例共 48 项 Rust 检查通过。Workspace 和新增测试目标严格 Clippy、引擎 / 工具 / 原生桌面构建以及资源只读校验通过；具体证据和待验收范围见[开发验证记录](../migration/acceptance.md#2026-年-10-月-27-日-m5-模拟室完整挑战流程)。
