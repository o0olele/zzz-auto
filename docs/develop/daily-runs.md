# M3 应用组每日计划

本批先接通按账号区服计算游戏日、应用组运行策略、按保存顺序逐项预检，以及由持久化成功记录决定当日跳过。当前已开放邮件与咖啡试运行及[分项记录和顺序交接](coffee-group-runs.md)，完整咖啡领取及真实游戏串联尚未验收。

## 设计

每个账号保存 `game_region`，采用参考项目的六种区服及日期偏移：国服、B服、亚服、港澳台服为 UTC+4 的日期，美服为 UTC-9，欧服为 UTC-3。这里的偏移已经包含每日重置时刻，并非区服真实时区；不使用电脑本地时区或夏令时推断。日期计算接收 UTC 时间，边界可由独立测试仓注入。

每组保存 `run_policy`：`always` 每次运行，`skip_daily_success` 跳过本游戏日成功的应用。旧配置及新建组默认 `always`，账号默认国服；启用按日策略前须核对区服。区服与策略通过配置修订、锁和备份保存，运行或原生请求未结束时拒绝修改。导入只转换旧账号文件的区服，凭据继续仅归档，旧运行记录不作为新版本成功证明。

导入读取 `config/NN/game_account.yml` 的 `game_region`，支持 `cn`、`cn_b`、`us`、`eu`、`asia`、`twhkmo`。缺省沿用旧版国服默认值并提示核对；未知值或类型错误拒绝导入，不猜测区服，也不输出账号凭据。完整原文继续归档。当前转换语义版本为 v3，预览指纹包含版本，规则升级后须重新预览；已有导入不自动覆盖。

计划保留完整顺序，对每项显示禁用、待运行、当日已完成或不可执行。任何启用的未知 / 未迁移应用仍阻止整组运行，不能靠历史记录绕过执行器检查。完成记录按账号及应用共享，不按应用组重复计算；所有启用项都完成时明确显示无需运行，不创建假成功记录或提交输入。

新的账号运行上下文冻结区服及开始时的游戏日。只使用本机账号历史中完整保存、开始和结束都属于该游戏日、成功且确认输入释放的邮件结果。诊断、旧版归档、缺少日期的旧原型记录、失败、停止、暂停、异常中断、未来时间及跨重置的运行都不作为当日完成。历史查询展示上限 100 条，完成判定另行扫描全部受限目录；坏文件提示并不作为完成，目录不可读或超过上限时拒绝启动。

后续咖啡组以分项时间和完成证明判断，咖啡还要求本次点单、电量、前置完成及返回大世界；后项失败或中断不抹去前项已经保存的成功。上一段整条记录规则继续兼容旧邮件记录，新组的失败、停止或暂停本身不证明成功，但已完成且保存的前项可单独用于每日跳过。跳过项不生成新的成功记录，继续时不改已完成分项，详见[分项完成规则](coffee-group-runs.md#账号历史和每日完成)。

启动仍携带配置修订，并增加预览游戏日。引擎重读配置和完成记录，在共用运行槽内再次核对修订、游戏日及预检期间是否发生其他运行，再开始邮件工作。跨重置的旧预览须重新生成；预览后另一运行已经完成时拒绝重复开始。完成记录读取在线程中进行，不持有运行状态锁。现有停止、暂停和完整输入恢复登记保持原含义。

预览附带引擎计算的 `valid_until`，桌面到时清除预览和输入确认；实际启动仍由引擎校验。启动被“已完成”或“日期过期”拒绝时，桌面清除本次预登记的输入恢复计划；已有暂停任务的登记不会被新请求覆盖。

## 使用

在“账号与应用组”核对并保存账号区服，在应用组选择运行策略并保存，再预览运行计划。按日策略下，计划会展示游戏日与跳过原因；当天全部完成后无需再次确认输入。若要主动再次检查邮件，将策略改为“每次运行”并重新预览。

## 验证

独立测试仓的 `daily_runs` 覆盖六区服重置、闰日与跨年、旧字段默认值、修订与账号隔离、完整成功及释放证明、跨重置 / 未来 / 旧记录排除、超过 100 条的完成查询、损坏提示、目录错误与数量上限、保存顺序以及不可执行应用不能靠完成记录绕过。邮件工作线程验证过期预览、持久成功后的跳过、停止后仍待运行、区服变化及并发启动唯一性；桌面回归验证保存、计划展示、无输入跳过及日期过期后重新确认。

```powershell
node scripts/prepare-engine.mjs
cargo test --manifest-path zzz-od-test/test/zzz_auto/rust/Cargo.toml --target-dir target/validation --locked --test daily_runs --test account_config --test group_runs --test mail_pipeline --test input_recovery --test regression --test elevation -- --test-threads=1
npm --prefix zzz-od-test/test/zzz_auto/frontend test -- --reporter=line
```

协议为 v13，桌面、引擎与生成类型须成套使用。新记录含分项进度时，同时核对分项成功、时间与输入释放证明，不一致的记录不作为每日完成。测试使用临时目录、固定图、真实 Maa 队列及模拟控制器 / 隔离窗口；未操作真实游戏或导入用户实际配置，本批未重打包便携 ZIP。实机每日重置与用户数据导入仍待验收。

## 实机验证进展

2026 年 10 月 17 日，用户按已成功运行邮件的同一账号核对区服、保存按日跳过策略、重新预览，再切回“每次运行”并预览的说明反馈“测试通过”。据此接受本游戏日成功邮件显示跳过、整组提示无需运行，以及恢复每次运行策略后计划恢复可运行的正常流程整体反馈。

本次仅验证计划显示，不登记新增游戏执行或成功记录，也不覆盖跨每日重置、多账号隔离及边界场景。按用户先验证主要功能的决定，接下来补齐咖啡正常点单到返回大世界的连续画面，推进咖啡完整执行和多应用连续运行。详细记录见[验收记录](../migration/acceptance.md#2026-年-10-月-17-日-m3-每日计划成功跳过实机验证)。
