## 已发现的不兼容与处理

1. 固定官方 Windows SDK 包未包含 `MaaDbgControlUnit.dll`；绑定的 `new_dbg` 创建失败。离线入口改用官方自定义控制器，提供固定 PNG 画面，不支持模拟点击换帧。完整邮件流程仍需要会响应动作的测试控制器。
2. 固定 SDK 对参考 WebP 通过 `set_encoded` 返回成功但尺寸为 0×0。离线入口用 Rust `image` 解码后编码 PNG，原生游戏截图仍经 Maa；这不是另建识别引擎。限制文件大小、解码尺寸和内存。
3. 绑定 1.25.2 的 `new_custom` 未保留回调 Box 的销毁所有权。适配器使用官方 sys 与回调表，显式持有回调，并在控制器销毁之后释放。
4. SDK `MaaTaskerPostRecognition` 返回 `MaaTaskId`，绑定 1.25.2 的 `job.get` 直接当成 `MaaRecoId`，详情查询失败。适配器用 task → node → recognition 获取结果，真实模板回归覆盖该路径。
5. 旧 OCR 的 LCS 语义与 Maa `expected` 正则不同；独立模板 mask、颜色过滤和模型预后处理尚未验收。生成资源带差异报告，全部游戏应用继续返回 `not_migrated`。

用户测试电脑已能发现并连接游戏，当前截图方式通过基础实测。参考目录仍未发现 ONNX 模型，M0 / M1 的剩余条件为：

- M1：截图的前后台、遮挡、最小化恢复、缩放与窗口失效诊断；前后台键鼠的点击、按住及释放。
- M1：Xbox / DS4、ViGEmBus、摇杆与转向；权限不匹配、引擎权限提升及崩溃后的独立输入恢复。
- M1：相同旧模型、输入和参数下的 OCR、闪光分类及代表 YOLO 的 CPU / DirectML 输出、完整延迟和 GPU 使用时段互斥。
- M1：带真实输入的排队、停止后无残留动作、异常失联及退出收尾；明确安全暂停及模型补充方案。无输入健康检查停止正常不能替代这些结果。
- M0 / M1：同机旧版性能基线、至少 30 个测量样本及 P50 / P95；确认关键链 P95 不超过旧版 110%、正常可控动作停止与释放输入在 250 ms 内完成的适用范围和可实现性。

后续阶段另行验收：M2 的完整邮件流程、领取确认与物品爆满分支、重复领取检查及业务暂停恢复；M3 以后的配置导入、账号、应用组；M4 / M5 的声音算法、战斗、两小时代表场景与百轮生命周期稳定性；M6 / M7 的服务、工具、插件与发行更新。上述项目不计为已通过的 M0 / M1 结果。

输入探针最长按住两秒，桌面可确认后启动，CLI 要求 `--allow-input`。键盘 `--key` 使用 Win32 VK 1..254；Xbox / DS4 使用官方 XUSB 位掩码，例如 A / Cross 为十进制 4096，LB / L1 为 256。按键释放经过队列完成确认；鼠标、摇杆、扳机与崩溃恢复尚未开放或验证。管道断线后取消任务并等待收尾；原生阻塞时不能宣称已在限时内完成退出。

当前 debug 桌面可执行文件只适用于本工程开发机；NSIS 配置已建立，但安装包、签名、离线模型完整包、便携版与干净环境未通过 M7 验收。

## 0.1.2 输入诊断

新增桌面“真实输入诊断”，支持前台 / 后台键盘、Xbox / DS4 数字按键，单次按住 1..2000ms、启动延时 0..10000ms。界面确认针对本次参数与游戏窗口，参数或窗口变化、失联和启动后均清除确认；引擎独立校验确认与参数。与截图、重连和健康检查共用唯一运行槽。协议升级为 v3，桌面和引擎需成套使用。

取消发生在延时阶段时不投递按下；已经投递的按下先等待完成，再释放。持有期间每次最多休眠 5ms 后检查取消，实际间隔受 Windows 调度影响。按下失败也尝试释放；释放或控制器恢复失败返回失败，保留未清理状态，重试成功之前拒绝新按下与控制器切换。停止响应仍为 stopping，收尾完成后保存终态与结构化计时结果。

独立测试仓新增 5 项 Rust 回归，总计 19 项：覆盖四种输入模式的参数与真实 Maa 自定义控制器队列、预先取消、延时取消、按下尚未完成时取消、持有时取消、释放时取消、停止后再次执行、按下与释放同时失败、控制器恢复失败、退出重试释放、普通固定图拒绝输入，以及引擎拒绝未确认 / 非法参数 / 未连接请求。自定义控制器记录按下、释放和恢复顺序，模拟原生回调部分失败；没有向实际游戏发送输入，也没有验证 ViGEmBus。

前端新增确认、参数变化、停止等待、计时展示、错误和失联检查，总计 4 项 Edge 流程通过；浏览器预览继续禁用输入，960px 无横向溢出。前端原生响应由测试模拟，只作为界面与协议证据。

`scripts/validate.ps1` 完整通过，包含格式、协议生成、引擎构建、严格 Clippy、19 项 Rust 回归、TypeScript / Vite 构建及 4 项前端流程。0.1.2 的 Windows x64 release 桌面与随附引擎构建通过；游戏输入与干净系统验收仍未完成。

0.1.2 便携 ZIP 已生成，并解压到中文与空格路径核对 54 个清单文件哈希。从包外工作目录运行包内引擎，版本为 0.1.2，SDK 从解压目录加载真实 v5.14.3；无输入 Pipeline 正常结束及 100ms 后取消通过。这仍是本机包验证，不计为真实游戏输入或 M7 验收。

`enqueue_us` 是投递按下的耗时，`key_down_ms` 包含原生按下完成等待；`held_ms` 从按下完成到准备释放计时，`release_ms` 包含释放与 inactive 完成等待。`stop_ms` 从引擎观察到取消到收尾完成计时，包含尚未完成的输入；不包含跨进程请求传输、取消检查间隔或控制器重建。`elapsed_ms` 包含探针启动延时，不包含控制器重建。原生操作成功只表示控制器完成，游戏实际响应、停止后无残留动作、完整停止延迟和同机 P50 / P95 仍待实测。

接下来使用测试包在游戏中逐项记录四种方式的响应与释放结果，并补鼠标、摇杆、权限与真实模型对照。M0 / M1 继续保持进行中。

## 0.1.3 键盘诊断修订

用户反馈 0.1.2 默认 W（VK 87）、按住 500ms、启动延时 3000ms 在前台 / 后台键盘均未响应，Xbox 360 正常。补充确认在可自由移动的大世界测试，游戏由米哈游启动器启动；未收到游戏或工具的实际权限数据。游戏锁定鼠标时先按 Win 返回工具，启动后在延时期间切回游戏。Xbox 数字按键登记为当前场景基础实测通过，不扩展为 DS4、摇杆或停止残留动作验收。

排查固定 SDK 的 [SeizeInput](https://github.com/MaaXYZ/MaaFramework/blob/v5.14.3/source/MaaWin32ControlUnit/Input/SeizeInput.cpp) 发现按下 / 释放调用 `SendInput` 后直接返回成功；[MessageInput](https://github.com/MaaXYZ/MaaFramework/blob/v5.14.3/source/MaaWin32ControlUnit/Input/MessageInput.cpp) 的同步键盘消息也直接报告投递完成。这能解释为何界面“完成”不能证明游戏响应，但尚不能证明本次未响应的具体原因。Windows [SendInput 文档](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-sendinput) 说明输入受进程完整性级别限制，正常从启动器启动不能排除游戏权限高于工具的情况。
