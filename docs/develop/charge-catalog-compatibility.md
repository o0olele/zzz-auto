# 体力目录与来源升级兼容

参考仓将区域巡防“迅雷与裂爪”更名为“迅脊与裂爪”。`ChargePlanItem::execution_mission_type()` 在所属分类内解析这一处精确别名，校验接受旧名，序列化与配置导入保留原文。它不在反序列化时改写名称，因此已有计划 ID、次数、冻结日志和前缀 SHA-256 均保持稳定。其他分类、近似名称和拼写错误不适用该别名。

桌面展示“迅雷与裂爪（现名：迅脊与裂爪）”，打开设置不触发保存。编辑目标次数仍保留旧名；用户显式选择现名才保存新名称，ID 和次数保持不变。新建计划只展示当前目录。现有目录已包含锋御、征服者和库萨里库，本次没有将这些既有项算作新增。

本次重新审核七份体力相关来源锁。目录只涉及上述名称变化；`TransportByCompendium` 新增的非空未知副本失败语义已由 Rust 的严格请求校验覆盖。快捷手册训练页配置和说明在上游撤销过黄色范围修正；本地保留已验证的宽黄色范围与完整文字匹配，不同步降低识别约束。出战节点新增 60 秒超时，在 `DeploymentRun` 中按累计活动时间落实；暂停不重置该时限，出战意图之后等待战斗使用父任务预算，投递前仍复验按钮阶段的剩余时限。通知沿用后续完整体力任务的失败上报，当前没有独立出战公开任务或重复通知通道。

快捷手册、关卡选择和出战构建器现在输出 schema 2。各自 `source-lock-v1.json` 冻结原 schema 1 来源；校验器只接受 schema 对应的精确来源清单，节点、模板及模型仍按生产定义复验。旧 schema 1 包继续读取；新旧来源与 schema 交叉替换、未知 schema 或重算清单哈希后的节点篡改均拒绝。其余执行包定义、协议 v47、导入预览 v19 和正式可用标记保持不变。

回归覆盖旧名导入标识、序列化、每日重置与日志恢复、三种资源的新旧版本和交叉篡改、界面显式更名及出战阶段超时。独立测试目标为 `charge_catalog`，界面用例位于独立测试仓 `charge-plan.spec.ts`。关卡选中证明、剩余副本执行和完整体力运行入口继续保留在同一开发目标中。
