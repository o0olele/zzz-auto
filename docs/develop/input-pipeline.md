# 实机带输入 Pipeline 诊断

本入口用于 M1 验证真实 Maa Pipeline 的按下、停止和释放，不执行邮件领取等业务，也不接收前端提供的节点、JSON 或入口名称。与直接输入探针共用控制器、运行槽、窗口身份 / 权限检查和输入确认；桌面发送前登记同一份崩溃恢复计划。

固定流程为按下一个数字键或鼠标键、短间隔无输入等待、释放。键盘和 Xbox / DS4 数字键使用 KeyDown / KeyUp，鼠标使用 TouchDown / TouchUp；不提供可能被 Pipeline 坐标规则解释为图像坐标的摇杆与扳机参数，它们继续走直接输入诊断。按住时间仍为 1..2000ms，启动延时为 0..10000ms。Pipeline 超时为 1..10000ms，从投递 Tasker 时开始，不包含启动延时、截图准备和控制器重建。

等待只拆分 DoNothing，单次不超过 25ms，不能重复执行按下。启动延时结束后重新验证游戏身份、1920×1080、键鼠权限及所选前台条件；鼠标先确认截图与坐标缓存。停止请求在延时、准备阶段也生效；进入 Tasker 后复用已有停止逻辑，等待任务及控制器队列结束，再显式释放声明的输入并等待 inactive。SDK 自动抬起只作为补充。原生阻塞仍须等待，超时不能伪装成输入已释放。

运行结果单独记录 Pipeline 的成功、失败、主动停止和超时，包含原生状态、投递、总执行、释放及取消收尾时间；SDK 在停止后仍可能报告 Succeeded，运行终态采用独立的结束原因。准备期间停止的收尾时间包含尚在执行的准备操作，可能长于不包含准备的 Pipeline 总耗时。不伪造直接输入的按下完成或实际持有计时；释放证明缺失时保留恢复记录并阻止继续运行。成功也只代表 SDK 执行及释放，游戏是否消费、是否有残留必须实机观察。

自动验证使用真实 Maa Tasker 与可记录的控制器、独立恢复和桌面回归；不把模拟窗口或离线成功当作游戏验收。发布后在原生诊断选择 Maa Pipeline、确认单次输入，再在延时期间切回游戏，分别检查正常完成、持有期间停止、超时及进程崩溃后的独立恢复。恢复不会重放流程。此入口只从桌面托管协议开放，以确保独立崩溃恢复先于真实输入；CLI 的直接探针保持现有边界。

## 实机验证记录

2026 年 10 月 16 日补充前台键鼠 W 持有期间超时验证：按住 2000ms、启动延时 5000ms、Pipeline 超时 500ms。用户确认角色移动一小段后停止，随后手动 W 正常；客户端结果为超时、输入已释放，投递 270μs、总耗时 588ms、输入释放 11ms、停止／超时收尾 85ms，详见[超时验收记录](../migration/acceptance.md#2026-年-10-月-16-日共用输入适配层-w-持有超时释放实机验证)。

同日将 Pipeline 超时改为 5000ms，用户在 W 持有期间切回工具主动停止，反馈符合预期。结果为已停止、输入已释放，投递 356μs、总耗时 1739ms、输入释放 10ms、停止／超时收尾 95ms，详见[主动停止验收记录](../migration/acceptance.md#2026-年-10-月-16-日共用输入适配层-w-持有主动停止实机验证)。

随后以鼠标左键、客户区坐标 `(960, 540)`、按住 2000ms、启动延时 5000ms、Pipeline 超时 500ms 验证持有期间超时释放，用户反馈测试正常；本轮未提供计时指标，详见[鼠标超时验收记录](../migration/acceptance.md#2026-年-10-月-16-日共用输入适配层鼠标左键持有超时释放实机验证)。以上均为共用输入层的单次观察；鼠标主动停止、其他按键 / 手柄与持有期间崩溃继续分别验收，计时不作为完整 IPC 延迟或 P95。

动作协议依据固定 [Maa 5.14.3 Pipeline 协议](https://github.com/MaaXYZ/MaaFramework/blob/v5.14.3/docs/en_us/3.1-PipelineProtocol.md)。项目计划与验收条件只维护在 [ROADMAP](../ROADMAP.md)。
