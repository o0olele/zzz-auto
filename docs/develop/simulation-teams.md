# 模拟室选队准备

该内部子流程从已打开的出战页开始，冻结体力计划采用的预备编队、完整二十槽位配置和脚本名称。指定编队时，先保存打开预备编队的意图，再在同一新帧核对“出战”和“预备编队”；复用已有清除原选择、按序选队和全表复核流程，确认返回出战页。保持当前队伍时只重新读取出战页，不打开列表。

依据为参考仓的实战模拟室、预备编队画面文档、`combat_simulation.yml`、`CombatSimulation` 和 `ChoosePredefinedTeam`。本流程只点击“预备编队”和选队列表，不点击“下一步”“出战”或“确定并出战”，不消费电量或写计划次数。关卡选中证明仍缺失，因此返回结果固定保留 `selection_verified=false`，不能据此开放完整体力应用。

父子共用控制器、暂停停止句柄和剩余活动预算。打开列表、各次选队输入及确认都先保存检查点；已投递或不确定投递的打开动作不重放。暂停后重新核对页面，选队未完成时复用原有全表重选规则，已经确认时仅重新检查出战页。保存失败、停止、超时或输入释放失败均阻止正常交回；保存终态期间收到的控制请求也必须处理。已完成检查点不能直接构造新的任务。

复用 schema 1 模拟室资源和已有日常选队资源，保持资源包中的原节点、协议 v45、导入预览 v18 及全部资源 schema。弹窗优先于背景，管理编辑页不能当作选队页；每次打开输入前重新截图，保持 1500ms 帧龄限制。真实出战页素材仍待补齐，开发组合帧和真实 Maa SDK 隔离控制器仅作开发验证。

`od_core::simulation_teams::TeamsFlow` 保存请求、打开回执及原 `TeamSelection` 检查点；`maa_adapter::simulation_teams` 复用固定模拟室 OCR 区域读取当前页面及复验打开操作；`zzz_engine::simulation_teams::TeamsRun` 负责子选队交接和父预算。正常结果仅由 `TeamsEnd::Prepared` 且已释放输入提供，调用者不能只检查快照中的完成字段。已完成检查点拒绝作为新任务；暂停发生在子流程确认之后时只重新核对返回，不重新打开或确认。

选队列表内继续复用原动态 Pipeline。每次翻页、切换或确认前，先检查固定弹窗区域，终止在弹窗节点时不得确认输入已完成；只有实际动作节点的完成记录才能推进。固定 OCR 在组合图中将“确定并出战”读为“确定並出战”，两种完整词均只用于拦截，不能据此点击确认。管理编辑页没有选择标记和预备出战按钮，不能用于本流程。选队确认的意图保存后，只有明确在原生投递前取消或超时才撤销；投递或不确定投递后暂停，即使列表仍可见也只等返回，不重选或再次确认。

没有新增桌面或 CLI 的真实输入入口，不修改账号配置、战斗脚本文件或计划次数。完整父任务仍须提供冻结关卡的选中证明，再串联卡片 / 电量、进入出战页、选队、出战、真实战斗及结算；当前类型和关卡投递回执不能替代此前置条件。
