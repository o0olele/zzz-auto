# 区域巡防单次挑战

本轮接通普通区域巡防的单次挑战，保留实机验收和正式运行入口。代理人方案培养和指定等级继续独立处理。参考 `area_patrol.py` 明确由快捷手册直接传送到目标副本，因此目标身份来自本次完整的分类、全名、前往、传送确认和实际入口路径；消费前还须用新帧读取区域巡防自己的详情、电量和下一步。不会改写模拟室关卡回执或把手工布尔值当作生产选中态。

父任务先冻结完整计划、编队、恢复策略、脚本修订、资源及窗口，预检全部下游能力并编译脚本，再发送首个导航输入。同一运行 ID、控制句柄及唯一原生槽位依次执行传送、电量与详情准备、选队、出战与前移、单战、结算。界面使用前台 CPU 会话，战斗按冻结配置切换输入与推理设备，暂停期间不更换目标窗口或重置活动预算。

区域巡防每次实际需要 60 电量；读取独立的 1525,1000..1650,1055 区域，不能套用模拟室数字位置。足额时保存下一步意图，见到本次出战页后交接选队；不足且允许恢复时保存打开恢复的意图，见到主弹窗才运行已有恢复子流程，返回详情后重新读取。禁止恢复或恢复后仍不足时返回明确不足，不增加次数。源代码已移除家政券流程，不新增过期操作。

出战与前移复用公共状态机，保留 60 秒累计出战等待、同帧复验、背包上限和低等级确认。战斗只接受本次正常完成及输入释放；失败、撤退和超时不能提供成功证明。结算须有本次完成意图并实际返回区域巡防详情；如出现已知战斗奖励弹窗，还须保存领取意图并确认。每次只执行一场，循环由体力父流程在保存计数并重新读取资源后继续，避免“再来一次”绕过次数提交。

区域巡防使用独立结果类别和私有执行 ID，不能借用模拟室或合成回执。计数沿用日志先于配置的提交、幂等、冲突保留和补交机制。传送快照、既有出战 / 战斗 / 奖励画面以及外部修改后的审计快照都不能恢复输入或登记成功。没有启动游戏，区域详情及完整挑战采用明确标注的组合回放，实际操作、等级、设备切换和异常恢复继续待验收。

内部单次父任务可由 `ChargeRegistrar::record_patrol_persisted` 登记，现已通过 `ChargeWorker::new_with_combat` 接入[体力父循环](charge-worker.md#区域巡防父循环)。父循环先冻结并编译启用计划的脚本，再以唯一原生槽位交接；正常结果先保存，之后返回大世界并重读资源。原 `ChargeWorker::new` 缺少战斗上下文时仍拒绝区域计划。专业挑战等剩余副本、正式入口和实机验收继续待办，不能标成完整体力应用已完成。

独立资源 schema 1 锁定 11 份来源、OCR 与全部只读节点。开发命令如下：

```powershell
cargo run --locked --target-dir target/m4 -p od-tools -- area-patrol-bundle --reference E:/Code/ZenlessZoneZero-OneDragon
target/m4/debug/zzz-engine.exe area-patrol-bundle-check
target/m4/debug/zzz-engine.exe area-patrol-inspect --image artifacts/area-patrol-detail-fixture.png
cargo test --locked --manifest-path zzz-od-test/test/zzz_auto/rust/Cargo.toml --target-dir target/validation-restore-charge --test area_patrol -- --test-threads=1
```

只读检查保持 `accepted=false`、`input_sent=false`、`completion_verified=false`，不提供运行或消费证明。模拟控制器使用真实 Maa SDK、已有战斗 / 恢复留档和明确标注的分类 / 详情组合画面，不能作为实机通过依据。
