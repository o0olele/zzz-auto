# M3 咖啡识别准备与顺序调度

本批交付咖啡只读资源与离线检查，以及可复用的顺序调度状态机，并让现有应用组邮件入口使用该状态机记录执行进度。咖啡尚不进入真实执行器清单；多个游戏应用的实际交接须等咖啡流程和输入清单具备验证条件。

## 咖啡现有证据与缺口

已阅读参考项目 `CoffeeApp`、`coffee_shop.yml`、咖啡店画面文档、地图传送实现和对应测试。旧流程包含三个传送点；六分街还需要转向及前移，澄辉坪和片刻闲可在传送后直接交互。候选咖啡为额外咖啡优先、汀曼特调兜底，喝后可能经过动画跳过、额外点单确认、电量确认或不可贪杯提示。返回大世界后还可能按配置启动体力计划。

现有真实截图只有片刻闲对话选项与已喝过对话；缺少点单后跳过、电量确认、不可贪杯、额外咖啡确认及六分街正常菜单等状态。两个不同的确认区域还有重叠，不能凭通用“确认”就判定领取成功。旧代码把对话标题消失当作已喝过，本轮只读检查不会据此发布咖啡成功。

因此本批仅转换固定 1080p 区域及锁定 OCR，检查两份真实截图中的汀曼大师、汀曼特调和“不喝了”选项。资源节点全部为 `DoNothing`，没有后继或输入动作；识别结果只报告可见信息，不判断已完成或修改账号每日记录。未知图像保持未知。

## 顺序调度规则

调度器接收已预检计划，保留启用项顺序及当日跳过项。同一时间只允许一个当前应用。启动项先生成检查点，完整保存后才能允许其输入；一个应用结束后先确认输入释放并保存结果，才能取下一个应用。检查点以递增编号确认，旧保存回执不能解锁新动作。

暂停期间保留当前应用和运行槽，确认输入释放后才进入暂停状态；继续保留当前应用而不从头开始。停止在边界和执行中都阻止投递后续应用。失败或未释放输入时终止整组；初版采用遇错停止，不声称已迁移旧版的失败重试策略。跳过不产生输入，也不伪造成新的成功结果。

现有邮件应用组接入上述状态机并把分项进度写入原运行记录；原有诊断记录保持兼容。生产预检仍只允许邮件一项，独立测试使用两个受控执行器验证顺序、保存失败、停止和暂停交接，不借此开放未迁移应用。

## 离线使用

需要已准备的固定 SDK 和 `sdk/models/ppocrv5`。以下命令只读取参考文件与截图，不连接游戏；生成目录仅用于开发预览，尚未加入正式发行清单。

```powershell
cargo run -p od-tools --locked -- coffee-bundle --reference E:/Code/ZenlessZoneZero-OneDragon
cargo run -p zzz-engine --locked -- coffee-bundle-check --bundle resources/generated/coffee-preview
cargo run -p zzz-engine --locked -- coffee-inspect --bundle resources/generated/coffee-preview --image zzz-od-test/screens/咖啡店/对话点单-选项.webp
```

生成器核对旧区域坐标与文字、固定 OCR / 字典哈希、来源与输出隔离及非受管文件。加载校验再次核对固定节点全集、无动作与后继、模型哈希和目录联接；改清单哈希也不能开放点击节点。输出 `options_visible`、`dialogue_visible` 或 `unknown`，附原生识别细节；这些状态均不等于当日完成。

独立验证入口：

```powershell
cargo test --manifest-path zzz-od-test/test/zzz_auto/rust/Cargo.toml --test group_schedule --test coffee -- --test-threads=1
```

真实截图报告保存在独立测试仓 `artifacts/m3-coffee-observations.json`。前端与引擎协议为 v13；分项进度仅用于展示与运行校验，重启后不从检查点自动重放。

## 后续验收素材

咖啡真实执行还需要补齐上述后态截图、选定传送点完整往返、确认弹窗的区分依据、额外咖啡及重复点单分支，再验证暂停恢复不重复点单、输入释放与下一应用交接。相关素材不足时保留明确缺口，不将模拟图测试当作实机通过。
