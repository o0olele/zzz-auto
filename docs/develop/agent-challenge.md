# 代理人方案的挑战与计数

本段继续接通完整代理人方案，沿用用户“暂不启动游戏，继续开发并保留实机验收”的选择。原始计划是逻辑身份，导航解析的具体副本是本次执行目标；二者不能互换写回配置。当前首先采用已有区域巡防、专业挑战和深度追猎执行器，模拟室仍需完成其生产选中证明和代理人关卡选择，不能因此被当作已完成。

在首个输入之前冻结导航、达成读取、对应挑战和战斗资源及编译脚本。导航回执须属于本次原计划、同一共享控制句柄并已保存、释放输入。由该回执生成的具体目标仅交给私有挑战构造路径，从实际到达进入详情准备，不重新做普通传送。区域和专业仍要求默认等级，追猎沿用指定等级、周常耗尽、深度 ON、实际费用和独立移动前置。所有阶段使用同一原生会话槽位、运行身份和活动预算。

参考 ChooseNextOrFinishAfterBattle 和 battle.yml：结算左下 610,1000..690,1055 的完整“已达成”才表示培养目标达成。读取须具备本次正常战斗和有效结算上下文，完成意图绑定同帧读数，发送前再次核对；暂停后不能用旧文字授权新动作。自己的完成已投递后保存该读数，领奖和实际返回仍沿用各副本证明。普通挑战不增加达成资源依赖。

正常单场完成仍只增加原计划一次，独立执行 UUID 去重。达成后仅在本次运行跳过该计划的剩余尝试，不把 run_times 填成 plan_times，也不改原类型、关卡、等级或脚本。未找到目标、实际不足和周常阻挡不增加成功次数；读数含糊时，保留已完成单场的真实计数并停止后续尝试等待验证。保存失败只补交原结果，停止状态下不再输入。具体终态和父循环、持久化边界以定向测试逐项验证，正式入口及每日成功仍待完整流程具备后接入。

目前无代理人培养实际详情及达成结算留档，使用明确标注的合成图和既有战斗、奖励、返回锚点验证；全部真实语义、布局、费用与操作保留实机验收。协议和资源兼容变化将在实现及验证后记录，不将独立只读检查或内部导航作为完整应用完成证明。

内部父循环现采用 `ChargeOutcome::Agent`，其中独立执行身份、具体目标和结果一同写入现有 schema 1 日志，旧普通回执格式不变。普通回执不能登记代理人计划，代理人回执也不能登记普通计划。`Unavailable` 必须没有目标，其他结果必须保留同次目标；周常阻挡只接受恶名狩猎的 1..3 次读数。原始计划、编队、恢复策略和共享控制句柄均在私有登记边界复验。

达成、无目标、实际不足或周常阻挡将计划加入本次跳过集合；集合由日志重放，不写进用户计划。后续循环的整轮最小值排除已跳过的代理人计划，普通计划继续按整轮扣减；真正进入下一普通轮时，沿用参考 `reset_plans` 将已跳过的代理人轮内次数清零。单场完成及独立执行身份始终保留在日志中，未确认的下一轮意图不会提前提交清零。没有进入下一普通轮时，保留已登记次数，不将跳过填成计划次数。读数为 `Unknown` 时返回 `NeedsVerification`，完成保存后返回大世界并以 `AwaitingVerification` 结束。

结算读取资源独立为 `agent-goal` schema 1，锁定八份参考文字来源和 PP-OCRv5；原区域、专业、追猎及模拟室包定义不变。正式应用仍为未实现，协议保持 v47，导入预览保持 v19。开发命令：

```powershell

target/m4/debug/zzz-engine.exe agent-goal-bundle-check
```

回放中修复父循环继续分派漏掉 `Agent` 阶段的问题，继续时由原代理人实例恢复其子流程，不能只清除共享暂停标记后重跑。另将追猎返回导航与战斗、费用及达成读取分开：已知街区加唯一完整标题，或奖励列表标题加已知副本名称，才提供追猎页面身份；等级菜单不作为详情返回。返回仍须匹配本页模板，消费仍由完整追猎识别和原状态机复核，1500ms 新帧时限不变。原先在导航中反复读取整套追猎状态会在并行回放负载下拖延新帧输入。

测试截图先生成再进入活动预算，控制器返回固定画面或快速编码后的本次资源读数，避免调试构建的大图压缩耗时混入截图新鲜度。该调整不扩大生产时限。首轮暂停遗漏、追猎超时及测试资源缺失均保留失败日志，再对修复后的路径定向复验。

模拟室已继续实现[详情目标解析与选择投递](agent-mission.md)：手册导航只解析本次具体类型，详情培养标记再解析具体关卡；原计划的“代理人方案培养”占位值不能作为已选关卡。生产选中证明仍须来自本次实际选择及其后态，才能交给现有卡片、恢复、编队和战斗流程。[实际双倍余量](charge-double.md)已接入内部读取与临时调度，[应用记录](charge-application.md)已接入历史和每日证明；完整模拟室消费、可靠无活动判断及正式桌面入口仍是完整体力应用的未完成门槛，不能以这三类内部挑战的完成替代。
