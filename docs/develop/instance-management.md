# M3 账号复制、删除与排序

本批补充“账号与应用组”中的账号管理，以及账号和应用组的顺序调整。沿用[账号配置基础](account-config.md)、[自动备份](config-backups.md)和[离线恢复](config-recovery.md)；只编辑本地编排，不登录游戏或自动开始任务。

## 使用与数据含义

在“编辑账号”选择来源，填写“新增账号名称”后点击“复制账号配置”。副本采用新的账号编号，复制区服、全部应用组及其顺序、名称、运行策略、应用顺序与启用项，包括未迁移和未注册应用。复制完成后编辑区选中副本，当前账号保持原值，副本默认不参与一条龙。原有组标识在新账号内保留，运行和历史始终同时使用账号编号区分；全局通用设置共用原值。

复制不复制账号凭据、导入原文、运行历史或每日完成记录，也不声称未迁移应用可运行。副本启用项可能包含尚无执行器的应用，运行前仍需完整预检，并手动核对实际游戏登录。账号名称为 1..80 个字符，复制时去除首尾空白；账号总数最多 128。

删除时选择非当前账号，点击“删除账号配置”，核对名称、编号和应用组数量后勾选确认。当前账号和最后一个账号不能删除；如需删除当前账号，先将另一个账号设为当前账号。删除请求必须显式携带确认，缺省为未确认，不能只调用写配置接口绕过。

删除仅从账号文件中移除该账号及其应用组，保存前先备份。运行历史、每日完成记录和导入归档保留，已用编号写入 `reserved_instance_ids`，后续新建和复制均跳过。通过配置备份恢复可以找回该账号并重新关联原有历史，保留编号集合不缩减。原有历史中的运行时名称不因删除或复制而改写。

“上移账号 / 下移账号”调整完整账号顺序，编辑对象和当前账号不变；“上移应用组 / 下移应用组”调整当前编辑账号的组顺序，当前编辑组保持不变。这些操作只修改本地展示和编排顺序，多个账号的自动登录与连续执行仍待迁移。

## 校验与生命周期

全部变更使用同一配置修订、目录所有权、写锁、修改前备份与临时文件完整替换。排序请求必须包含全部原有标识各一次，拒绝缺项、重复、替换或额外标识；不能用排序实现删除。无效输入、旧修订或备份失败均不替换当前文件。

引擎所有配置修改现已复用导入及恢复的工作保护：运行、暂停、停止收尾、原生操作、未保存结果和未确认释放的输入会拦截。文件工作由阻塞线程持有互斥直到完成，请求方断线不提前释放。记录保存失败后先在账号历史中重试保存，再修改配置。

界面切换账号、应用组、重新读取、修订变化、运行条件变化和断线会清除删除确认；账号与应用组的两个删除确认不会同时打开。冲突读取最新配置后要求重新操作，写入失败撤销账号删除确认，不自动重试。断线或切页后的迟到响应不能重选副本、恢复旧表单或显示成功。修订变化继续使已有应用组运行预览及输入确认失效。

协议升级至 v21，桌面、引擎和生成类型须配套使用。账号文件仍为 schema 1，未新增数据字段；保留编号复用 v20 字段。运行资源格式不变，schema 1 / 协议 15..21 与 schema 2 / 协议 16..21 兼容，拒绝更高或未知协议。已有资源包无需为本批界面和编排功能重新打包。
