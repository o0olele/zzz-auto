# M3 运行结果提醒

按账号保存关闭、仅异常或全部结果三种策略，默认仅异常。桌面为本会话明确启动的应用组冻结策略；结果提醒保存在宿主中，可跨页面、隐藏到托盘及断线后查看。程序内显示最新未读提醒，独立页面提供已读和清除，托盘显示未读数并可打开提醒页。

提醒区分正常完成、失败、主动停止、记录未保存、输入未释放及连接中断。成功须确认整组结果、保存和输入释放；记录重试成功后可以再确认最终结果。相同错误及重复快照只提醒一次。重连和重启不补发历史任务，退出不产生新的中断提醒。最多保留 32 条，超出时明确计数；提醒是本次桌面会话缓存，持久记录仍在运行历史。

旧账号 `notify.yml` 的 `enable_notify` 可转换关闭或全部结果，应用、节点和远程渠道配置归档并提示兼容范围。首批迁移本机结果提醒，外部渠道和节点通知继续保留待办。旧文件缺少新对象时只读补默认值，复制、备份和离线恢复保留策略并展示。

验证使用隔离配置、模拟运行快照、桌面管道及界面替身；不运行用户游戏或发送外部消息。真实 WebView2、托盘显示和正式包环境待实机验收。

## 使用与保存

在“账号与应用组”选择编辑账号，在“运行结果提醒”保存策略，再从一条龙运行页开始应用组。设置只影响之后接受的新任务，运行中的策略保持原值；独立诊断不会产生应用组提醒。各账号的设置独立，设为当前账号不会切换游戏登录。

出现未读提醒后，任意页面的提示可进入“运行提醒”。页面显示运行时账号、组名、运行 ID、时间与结果，可标记已读、筛选全部及清除已读；断线时仍可操作本地缓存。托盘“运行提醒”菜单显示未读数，点击后打开主窗口并进入提醒页。输入恢复和记录重试沿用原入口，标记提醒不会执行恢复或重新启动。

配置保存为 `instances[].run_notifications.mode`，允许 `off`、`errors`、`all`，缺少整个对象时只读补 `errors`；显式对象缺字段、未知枚举或额外字段拒绝读取。旧 `notify.yml` 缺少开关时按旧默认开启转换为 `all`，关闭转换为 `off`，不解析或公开远程凭据；源文件仍按字节归档。协议为 v28、导入预览 v8，旧账号 schema 保持 1。

宿主最多保留 32 条提醒及最近 128 个登记标识，重复快照和重复启动回执不会反复提醒。已读及清除只处理本次提交的标识，期间新到的提醒保持未读；迟到响应不能覆盖更新的提醒版本。提醒仅反映当前桌面明确接受的应用组，重连后通过运行历史检查未确认结果，桌面重启不恢复会话缓存。
