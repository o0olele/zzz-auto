# M3 账号与应用组咖啡设置

在“账号与应用组”选择账号和应用组后，可以保存汀曼特调 / 浓缩咖啡、超时及启动 / 继续延时。配置位于 `config/accounts.yml` 的 `instances[].groups[].coffee`，沿用旧版按账号和组分别保存应用参数的粒度。当前路线固定为澄辉坪 → 汀曼咖啡，完整领取仍待实机验收；后续已接通[应用组咖啡与邮件交接](coffee-group-runs.md)，按保存参数试运行。

## 保存与复用

默认值为汀曼特调、60000ms 超时、3000ms 延时；超时允许 1..60000ms，延时允许 0..10000ms 整数。Rust 定义选项、默认值和范围，连同协议生成到桌面表单；咖啡诊断也使用这些定义，原诊断表单的初始延时从 5000ms 统一为 3000ms。

旧账号文件缺少整个 `coffee` 对象时只读补入默认值，不因读取而写盘；对象存在时必须包含全部三个字段，拒绝未知字段、未知咖啡、空对象、null 及越界值。配置仍为 schema 1，保存后旧引擎无法识别新增字段，回退须使用保存前备份。当前桌面与引擎协议为 v24，保留 schema 1 / 协议 15..23 及 schema 2 / 协议 16..23 的运行资源包兼容，资源内容无需重新打包。

保存复用配置修订、文件工作互斥、自动备份及完整替换。运行、暂停、收尾、未保存结果或遗留输入时不能修改；旧修订返回冲突，桌面读取最新值后要求重新编辑。保存失败保留草稿，不显示成功。切换编辑账号或组、读取新修订、切页或断线会丢弃未保存的咖啡草稿；配置变化后原应用组运行预览失效。

复制账号或应用组会复制咖啡参数，副本之后独立编辑；新账号和新组使用默认值。备份恢复、离线恢复和导入预览均展示咖啡参数，恢复前可核对实际变化。

在“原生诊断 → 咖啡点单试运行”的参数区域选择账号和应用组，点击“采用所选组咖啡配置”，将保存值填入本次表单；选择来源、采用或重新读取都会撤销输入确认。随后仍可临时调整、选择起点并确认启动。本入口只读取参数，不切换当前账号或游戏登录，不回写配置，不写账号每日成功记录。任务开始后冻结本次参数；运行或暂停期间不能再次采用其他组，切页返回显示实际运行参数。读取配置失败时显示错误并可重试，用户仍可手动填写本次诊断参数。

## 旧咖啡配置检查

导入预览升级为 v5，旧预览确认须重新生成。针对每组，优先检查 `config/<两位账号>/<组>/coffee.yml`，仅在组内文件缺失时检查旧 `config/<两位账号>/coffee.yml`，与参考 `ApplicationConfig` 的迁移优先级一致。

旧咖啡配置仅定义地点及咖啡后体力计划，选单由体力计划动态决定，没有可直接转换的新固定咖啡、超时或延时。预览为新字段采用默认值并明确要求核对；旧地点不是 `澄辉坪 - 汀曼咖啡` 或缺省时提示当前固定路线不适用，旧后续体力计划启用时提示尚未迁移。这些旧字段保留原始字节，不作为已经完成行为迁移。预览不输出未知值或原文；已知字段类型损坏时报错，错误只给出文件名。

归档、源变化校验和首次导入保护保持原规则。同一导入再次执行保留用户之后保存的咖啡设置，不覆盖已有配置。此前已导入的数据不自动重新导入，需要在桌面选择固定咖啡参数。未知应用及旧咖啡启用值继续保留；当前咖啡可进入应用组试运行，未知或其他未迁移的启用项仍阻止整组运行。
