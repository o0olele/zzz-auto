# 代理人方案培养

参考 CompendiumChooseMissionType、CombatSimulation.choose_mission 与 cv2_utils 的头像定位：计划没有指定代理人姓名，使用页面提供的培养目标标记。手册普通训练区域为 1254,376..1312,894，恶名狩猎改用 1254,552..1312,894 以排除上部分层条；标记中心向上 80 像素作为对应条目的定位基准，再配对下方的前往。模拟室详情则在 128,740..1798,776 的名称顶部区域找到标记后向下 80 像素选择目标。

标记来自 RGB→HSV 后，反选 H≤10、S≤10 的低饱和背景，并以面积至少 800 的外轮廓过滤。它提供培养目标位置，不证明角色身份或关卡选中。导航仍须同次训练分类、标记与前往配对、自己的传送确认及实际到达；缺失目标时有限滚动，不能改走普通副本或把找不到当成功。

到达后的代理人目标、普通副本准备及“已达成”收尾由[代理人挑战](agent-challenge.md)独立接入，保留原计划 ID 和计数语义。区域、专业和追猎已接入内部父循环，模拟室详情目标解析及投递已接通，生产选中证明仍待完成。当前没有代理人方案真实留档；几何检测和后续状态使用明确标注的合成素材验证，真实语义、布局和操作保留实机验收。用户已选择暂不启动游戏，正式执行入口与完整目标继续待办。

当前实现为纯 Rust 候选检测，不新增生产 Python 依赖。参考仓现有环境中的 OpenCV 4.13.0 只用于独立生成离线对照：全部 16,777,216 种 RGB 的掩码摘要一致，14 组合成图的外轮廓面积、顺序、边界裁切、嵌套过滤和定位偏移一致。初测发现 ROI 左边界轮廓缺失，补零边框后复验通过。检测结果含像素指纹用于后续滚动定位，不能作为角色身份、到达或选中证明。

`agent-markers-inspect --image <1080p PNG> --area training|hunt|simulation` 不加载 SDK，返回候选及来源，所有验收、输入、导航、选中和成功标记保持 false。单张图标记缺失时不推断目标不存在或计划完成；正式执行入口继续关闭。

[代理人传送](agent-transport.md)已加入内部独立状态机和资源，不修改原普通传送包定义。四种训练分类共用训练页签、选中分类及自有传送确认；同帧将参考顺序的首个标记、下方最近“前往”和其对应的唯一完整副本名称配对。原计划保留，具体目标和标记像素指纹在投递前保存，投递前重读不一致则撤销尚未发送的意图；已投递“前往”后不替换目标。暂停继续保留已投递意图，实际到达只授权后续目标准备，不提供消费、完成或次数证明。

模拟室已继续接通[培养详情的具体关卡解析与选择投递](agent-mission.md)：在本次实际导航保留的具体类型内，按顶部第一个培养标记配对完整名称和点击位置，投递后保存原目标并回读。独立父流程保留原始计划，未找到与待验证分别结束；回执仍未验证选中，完整模拟室消费与计数继续保留门槛。

缺少标记或对应按钮时，只在已核对训练分类与已知副本列表的页面有限滚动。十次自有滚动后仍无候选，返回单独的“未找到目标”；未知页面、无法读取的名字或到达冲突不能采用这个结果。完整父流程还需据此返回大世界并跳过本次计划，不能当作培养完成。
