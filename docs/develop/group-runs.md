# M3 应用组试运行与账号记录

本批将保存的账号与应用组接入运行入口，并增加按账号查询记录。沿用已有邮件 Pipeline、共享运行槽、暂停 / 继续及独立输入恢复，不改邮件画面和领取步骤。2026 年 10 月 17 日用户确认应用组邮件运行正常、账号历史可见，正常流程实机通过。旧版应用组会顺序运行启用项并检查每日记录；当前只有邮件具备试运行执行器，因此先明确支持范围，不将登记清单当作可运行清单。

## 运行范围

“账号与应用组”页面可以预览完整的保存顺序，分别显示未启用、邮件试运行、尚无执行器和未知应用。运行前重新读取配置并核对修订、当前账号和组内容；任何启用项不可执行、没有启用项或所选账号不是当前账号时，整组拒绝启动，不部分执行。当前只允许启用邮件一项，其他应用继续迁移；不自动切换游戏登录账号。

启动请求必须确认游戏登录账号与所选当前账号一致，并确认真实输入；客户端不提交可替换的执行列表。引擎冻结账号编号、显示名称、组 ID 和配置修订，将它们写入本次记录，再投递原有邮件工作。启动记录保存失败时不产生游戏输入。暂停 / 继续使用原运行 ID，期间仍拒绝配置修改。桌面发送请求前登记邮件的完整输入恢复计划，与原生诊断入口遵守同一恢复规则。

## 保存与查询

账号运行记录保存到宿主数据目录的 `runs/accounts/<四位账号编号>/<运行ID>.json`，例如账号 1 使用 `runs/accounts/0001/`；文件包含版本和完整运行结果。诊断入口继续保存原来的 `runs/<运行ID>.json`，不猜测旧记录属于哪个账号。每条记录只保存在对应目录中，临时文件同步落盘后完整替换，拒绝目录联接与无效账号路径。账号和组名称只作为记录内容，不拼成路径。

结果保存失败进入状态快照并显示错误，保留尚未写入的完整记录，阻止新任务。修复数据目录后，点击“重试保存运行记录”只保存失败的记录，不重新执行游戏动作；仍不能保存时保持拦截。暂停任务继续或停止后的结果成功写入，也会清除此运行的保存错误。引擎退出后内存中的未保存结果无法补回，历史保留最后一次成功写入的内容，并按上述中断规则展示。

查询只返回指定账号最近 100 条记录，核对文件名、账号归属、版本及结构；结果超过 8 MiB 时减少条数，并提示更多历史仍在数据目录。单账号目录最多扫描 10000 项，超过限制要求先归档旧记录。损坏文件单独计数并提示，不伪装成无历史。运行记录中没有终态、且当前引擎没有持有同一账号与运行 ID 时，查询标记为“异常中断”；保留原始记录和未知结束时间，不修改输入释放证明，也不自动恢复游戏操作。

## 桌面使用

1. 在总览连接游戏窗口，手动确认已登录的游戏账号。
2. 打开“账号与应用组”，将对应配置设为当前账号，暂时只启用邮件。
3. 点击“预览运行计划”，核对账号、配置修订、启用项及阻止原因。
4. 核对预览显示的延时与超时，勾选本次账号与前台输入确认，点击“开始应用组试运行”，在延时内切回游戏。
5. 在同一页面暂停、继续或停止，查看按账号保存的记录。继续使用本次运行相同的延时；暂停期间仍占用运行槽。

延时默认 3 秒，超时默认 60 秒，可在[通用设置](general-settings.md)保存。应用组启动参数由引擎重新读盘并冻结，客户端不提交邮件参数；保存通用设置也会使旧预览的修订失效。

账号、组、配置修订、窗口、截图方式或连接变化后需要重新预览并确认。原生诊断中的“邮件流程试运行”继续作为独立诊断入口，它的结果不合并到账号历史。应用登记的正式可用标记仍保持待验收。

账号区服与应用组每日策略已接通，详见[应用组每日计划](daily-runs.md)。旧运行记录继续只读归档，缺少游戏日的新原型旧记录也不作为当日完成。领取是否已经生效仍由邮件画面检查决定。

## 验证

独立测试仓覆盖保存顺序与整组预检、旧修订 / 非当前账号 / 空组拒绝、确认校验、启动前写盘失败无输入、账号记录隔离、历史排序与损坏提示、重启后中断标记，以及真实邮件工作线程的暂停 / 停止 / 结果持久化。桌面回归覆盖确认失效、配置变更后重新预览、运行控制和按账号历史。所有游戏执行验证使用既有固定素材和可反应模拟控制器。

```powershell
node scripts/prepare-engine.mjs
cargo test --manifest-path zzz-od-test/test/zzz_auto/rust/Cargo.toml --target-dir target/validation --locked --test group_runs --test mail_pipeline --test input_recovery --test account_config --test regression -- --test-threads=1
npm --prefix zzz-od-test/test/zzz_auto/frontend test
```

协议为 v13，桌面、引擎和生成的 TypeScript 类型需成套使用。新记录可选包含顺序调度检查点及分项进度，当前运行和账号历史均可展示；旧记录保持兼容。保存结果或输入释放未确认时不交给下一应用，详见[咖啡识别与顺序调度](coffee-and-groups.md)。当前生产入口仍只执行邮件，未对用户旧数据执行导入，也没有把调试工作线程或模拟控制器测试作为新增入口的实机验收。

## 实机验证进展

2026 年 10 月 17 日，用户按应用组邮件正常流程的试用说明反馈“运行正常，历史可见”。据此接受从所选账号与应用组发起邮件试运行，以及在对应账号历史中查看结果的整体反馈。未提供运行 ID、截图、具体参数或耗时，不补记这些值；重启后持久性、多账号隔离、每日跳过、旧配置导入及多应用连续执行继续待验收。

按用户先验证主要功能的决定，下一项验证通用设置保存、切页后读取及应用组使用保存的邮件参数。暂停、停止、保存失败与异常恢复等实机边界后续再安排。具体记录见[验收记录](../migration/acceptance.md#2026-年-10-月-17-日-m3-应用组邮件与账号历史实机验证)。
