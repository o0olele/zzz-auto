# M3 配置备份查看与恢复

本批接通现有账号配置自动备份的桌面入口，用于撤销账号、应用组和通用设置的历史修改。入口位于“账号与应用组”，先读取备份列表、选择并预览差异，再确认恢复。当前配置必须可正常读取；损坏或缺失配置可使用总览中的[离线恢复入口或原生命令](config-recovery.md)。

## 数据与约束

备份限定为当前数据目录 `config/backups/accounts-r<修订>-<UUID>.yml`，不接受任意路径或其他 YAML。列表按修订从新到旧最多显示 50 份，明确显示更多备份及不可用文件的数量；目录扫描有数量限制。列表只读元数据，预览时才读取并严格校验内容。链接、目录联接、超长文件、不支持的 schema 和未知字段被拒绝，错误不包含 YAML 原文。

预览返回当下配置和目标备份的可公开字段，包含账号、当前账号、区服、应用组顺序、启用项、按日策略、截图、邮件参数和快捷键。确认同时绑定当前修订、当前有效配置、备份原始字节及备份标识；任何变化后须重新预览。恢复在配置锁内重新读取并校验，保留当前导入来源，只允许相同来源的备份。

恢复复用现有保存逻辑：先备份当前文件，再原子替换账号配置，修订从当前值递增，不能退回备份的旧修订。记录、导入归档、资源选择和模型缓存保持原值。恢复不会登录游戏或启动任务；新旧账号仍需用户核对实际登录状态。恢复后可选择刚保存的备份再次恢复。

恢复移除的账号编号记入可选的 `reserved_instance_ids`，以后新增账号不复用。再次恢复可找回原账号，但保留编号集合不能缩减，避免新账号读取旧账号的历史和每日完成状态。旧配置缺少该字段时按空集合读取；产生保留编号后的文件须由当前版本读取。

## 桌面与引擎

文件工作在专用阻塞线程完成，复用配置导入的运行互斥和生命周期持有。运行、暂停、停止收尾、原生操作、遗留输入或未保存运行记录时拒绝恢复；请求方断线不提前释放在途文件操作。保存结果未确认时应重新读取配置，不自动重试写入。

更换备份、配置修订变化、任务开始、资源切换、切页或断线会清除预览与确认。恢复后刷新账号和通用设置，宿主按返回配置重新注册快捷键；所有旧应用组运行预览因修订变化而失效。

协议升级至 v20，桌面与引擎须配套更新；账号文件仍为 schema 1，新增可选的保留编号集合。运行资源格式不变，schema 1 的协议 15..20 和 schema 2 的协议 16..20 继续兼容。后续离线恢复复用同一备份列表扫描和严格校验规则，不更改协议。真实用户目录中的预览、恢复和恢复后参数生效仍待实机验收。

## 验证与试用

新增 9 项 Rust 备份用例，加上账号 15 项、应用组管理 7 项、每日计划 7 项、应用组记录 8 项、原生引擎运行 / 暂停及未保存结果拦截 2 项、资源兼容 1 项，49 项针对性回归通过。新增界面 8 项及既有账号 / 设置 23 项共 31 项通过；明暗主题和 960 像素宽页面已检查。主 workspace 和新增测试的严格 Clippy、格式检查、生产前端及配套原生 debug 桌面构建通过。用例均使用临时目录、模拟界面及离线游戏控制器，不修改真实用户配置或操作游戏。

```powershell
cargo test --manifest-path zzz-od-test/test/zzz_auto/rust/Cargo.toml --target-dir target/validation --locked --test config_backups --test account_config --test group_management --test daily_runs --test group_runs -- --test-threads=1
npm --prefix zzz-od-test/test/zzz_auto/frontend test -- config-backups.spec.ts accounts.spec.ts
```

重启配套桌面，在“账号与应用组”点击“读取配置备份”，选择一份备份并预览，核对当前账号、将移除或找回的账号、应用组顺序、启用项和通用设置。确认后修订应增加，账号及通用设置应刷新；重新读取备份列表可找到恢复前的配置。首次保存配置之前没有自动备份，当前文件损坏时本入口不能取代离线修复。
