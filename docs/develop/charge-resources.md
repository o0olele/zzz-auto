# 快捷手册体力资源读取

`NativeSession::inspect_charge_resources` 复用已校验的快捷手册执行包、CPU 和 ppocrv5，读取同一帧的当前电量、储蓄电量与以太电池。先验证无遮挡的快捷手册上下文，再读取原 `资源栏` 的 `[1220,35,550,75]`，不投递输入，不修改配置或计划次数。

解析沿用参考实现的三个相对中心 173 / 348 / 485，支持数字右对齐导致的整体位移。三项都须唯一且完整，重复候选、越界、无效数值或任何缺失都返回未知，不以零填充，也不选择“最近”的冲突值。完整电量分数须保留 240 分母；白字过滤使灰色分母消失时可读取当前三位以内的整数。固定图中斜杠被 OCR 识别为 1 / I / l 时，仅在剩余文本是三位以内当前值和完整 240 后缀时正规化，拒绝将 `0421240` 当作巨量电量。

同帧分别读取 RGB 208..255 的白字和原色。两边都有完整结果时须一致，只有一边完整时采用该完整结果，不跨帧或跨字段拼数。两边都不完整时，沿同帧检测框扩边做单行复读，保持 0.6 置信度；这补充了检测器将细字“4”只框住一部分的情况，不降低阈值或把字母替换成数字。当前电量按固定三位显示解析，拒绝将没有合法分隔结构的长数字当作电量。

双倍余量只在训练页、模拟室蓝底选中、基础材料及其前往上下文和完整“每日怪物卡双倍掉落次数”标签下读取 `0..5/5`。完整标签可由同一行相邻文字框组成，独立次数按参考使用单行识别；两处含次数时必须一致。`0/5` 只证明余量耗尽，其他分母、咖啡增益 `1/1`、其他页签或未命中标签继续返回未知。实际资源检查及双倍临时计划已接入内部父流程，可靠无活动判断与生产选中证明仍待完成，详见[实际双倍余量](charge-double.md)。

原生只读入口：

```powershell
target/debug/zzz-engine.exe compendium-inspect --image zzz-od-test/screens/快捷手册/目标TAB.webp --read-resources
cargo test --locked --manifest-path zzz-od-test/test/zzz_auto/rust/Cargo.toml --target-dir target/validation-restore-charge --test charge_resources -- --test-threads=1
```

保持 `accepted=false`、`input_sent=false`。资源数值不是关卡选中证明或挑战成功证明；暂停、停止和父预算仍由完整运行编排处理。独立取消会丢弃在途结果，不把原生同步识别当作可立即中断。

内部父流程现通过 `read_charge_resources` 读取原生新帧。三项数值仍须同帧完整提供；截图、识别或返回时已取消、耗尽预算或帧龄超过 1500ms 时丢弃整份结果，不拼接历史值，见[体力父流程](charge-worker.md)。

6 项 Rust 检查通过，其中真实 Maa SDK 对照原 19 张资源栏截图，覆盖数字位数、超过 240、粗体及原问题截图；输出见 `artifacts/charge-resources-corpus.json`。另外核对目标页、专业挑战训练页、带咖啡 1/1 的模拟室训练页、大世界和遮挡后的未知结果，取消及零预算也不产出可采用结果。两张训练页分别读到 42 / 67 / 27 与 141 / 67 / 27；双倍活动的真实五次正例及不存在证明继续待补，现有组合文字解析不能算实机通过。原生 CLI 已在隔离数据目录中读到 86 / 2400 / 5，仅创建 Maa 日志，没有创建账号配置或运行记录。
