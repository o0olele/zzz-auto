# 模拟室传送与选关父流程

`SimulationApproachRun` 将快捷手册传送和模拟室选关串成同一内部任务，冻结运行 ID、完整计划、游戏窗口、截图方式和总活动预算。流程依据沿用[快捷手册传送](compendium-transport.md)与[关卡选择投递](simulation-mission.md)，没有新增画面区域或输入动作。

构造时校验两份资源并冻结清单哈希；执行、继续和阶段交接重新完整校验。选关资源缺失或变化会在传送输入之前拒绝。实际游戏通过外层持有的唯一 `NativeSession` 槽位取得前台键鼠 / CPU 会话，交接前等待旧队列并释放输入；隔离回放仅复用已有控制器。暂停后允许外层销毁会话，继续重新装载当前阶段资源。

传送的实际到达、输入释放和终态保存全部完成后，才保存选关阶段并执行关卡选择。阶段保存失败、停止、父预算耗尽或输入未释放都阻止后继；保存错误不会被同时出现的超时覆盖。执行期间全部资源校验、装载、识别、输入、保存与收尾共用一个活动预算，暂停时间不累计；外层在构造冻结资源之后重新计算并传入自身剩余预算。

父子共用暂停停止句柄；传送确认、关卡选择已经投递时不重放。子流程返回后、父流程终态保存期间收到暂停，也会在继续时撤销旧到达 / 选关回执并读取新帧。若暂停发生在已保存的阶段交接处，则从尚未执行的后继开始检查当前画面。停止不能被继续覆盖，父流程不终结外层的控制句柄。

当前关卡子流程只能返回 `selection_verified=false`。父流程因此以 `AwaitingVerification` 结束，保存运行 ID、计划和未验证回执；仅实际返回此终态、输入已释放且没有待处理控制请求时，`receipt()` 才提供该回执。它不产生卡片准备、恢复电量或出战入口，不写计划次数、每日成功和应用完成，也不提供人工设为已验证的开关。旧快照不能直接作为新任务恢复入口。

协议 v46、导入预览 v19、资源 schema 和正式可用标记保持不变。关卡选中态素材与识别生产者、后续准备及单战的完整编排、体力运行登记、实际设备交接和全部实机验收继续保留。
