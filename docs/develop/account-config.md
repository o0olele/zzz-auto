# M3 账号与应用组基础

2026 年 10 月 16 日开始 M3。首批交付账号与应用组的独立数据、旧 YAML 导入预览、修订冲突检查及桌面编辑入口；随后接入[应用组邮件试运行与账号记录](group-runs.md)、[通用运行设置](general-settings.md)和[应用组每日计划](daily-runs.md)。咖啡等新游戏流程、多应用执行及资源下载继续在 M3 后续实现。

## 数据与导入约定

引擎使用宿主指定的数据目录，账号及应用组保存到 `config/accounts.yml`。每次修改携带读取时的修订号，在文件锁内重新读盘并校验；冲突返回最新配置。保存前备份旧文件，临时文件同步落盘后完整替换。损坏或未知版本不能回退成默认值。运行中、暂停中、停止中及原生请求未结束时拒绝修改，账号切换不会登录游戏。引擎与离线导入工具还共用数据目录占用锁，离线导入前须退出使用该目录的引擎；桌面导入由当前引擎执行，同一目录只允许一个引擎持有。

提权切换保留“先启动候选进程、取消授权仍保留旧引擎”的行为。候选进程完成身份配对后等待首个请求；桌面确认旧引擎退出后，才发出请求并初始化候选引擎、接管数据目录。初始化失败返回结构化错误，不绕过目录占用锁。

桌面入口见下方“桌面导入”；源码 CLI 为 `od-tools import-config`，显式指定旧程序目录和新数据目录。默认只读预览，列出账号、应用组、归档文件及待迁移项，不输出 YAML 值或账号密码。应用导入必须提供预览指纹；源文件变化后需重新预览。新数据目录不能与旧目录重叠。

读取 `config/one_dragon.yml` 的账号列表，以及 `config/NN/<group>/_group.yml` 的有序应用列表；默认组不存在时兼容 `one_dragon_app.yml` 的 `app_order` / `app_run_list`。保留未注册应用的顺序和启用值，新登记的默认应用补在末尾并禁用。实例编号、名称、当前实例及参与一条龙的标记保持原含义。

源目录内非 sample 的 YAML 按原始字节归档到新目录的 `imports/<指纹>/config/`，包括未知字段、各应用设置、账号凭据和旧运行记录。这些内容只在本机保存，不通过 IPC、日志或桌面快照返回；归档不是新引擎已经支持这些字段的证明。当前转换账号及区服、应用组、可兼容的截图设置与任务快捷键，其他字段在预览中明确列为待迁移；截图转换见[通用设置说明](general-settings.md#旧配置导入)，快捷键转换见[全局任务快捷键](global-shortcuts.md)，区服见[每日计划](daily-runs.md)，咖啡兼容检查及当前 v5 预览规则见[咖啡设置](coffee-settings.md#旧咖啡配置检查)。旧运行记录不转成新版成功记录。

首批导入只允许空白配置；同一份导入重复应用不覆盖后续编辑，其他导入拒绝覆盖已有配置。归档完整写入后才启用账号配置，失败可重新执行；修改前的配置备份位于 `config/backups/`。符号链接、目录联接、非 UTF-8 / 损坏 YAML、重复编号与重复应用等明确报错，不跳过后声称完整导入。

## 使用

### 桌面导入

在“账号与应用组”选择旧程序 `config/one_dragon.yml`，或填写旧程序根目录，再点击“预览旧配置”。预览显示账号、当前账号、区服、应用组顺序、截图设置、归档文件和待迁移说明；不返回账号凭据或 YAML 原文。核对后勾选确认再执行导入，目标固定为当前引擎的数据目录。

桌面与命令行共用核心导入器。引擎持有目录占用锁，在空闲时预览或导入；文件扫描和归档放入工作线程，期间拒绝游戏任务及配置修改。源文件变化会使确认失效；已有配置拒绝覆盖，同一导入再次执行保留后续编辑。导入结果响应丢失时，重新读取配置或重新预览即可核对，不自动重试写入。导入不登录游戏。

首次导入前不要保存默认账号或通用设置。若当前数据目录已有正式配置，只能预览，不能覆盖。界面切页、断线或更换源目录会清除预览与确认；导入完成后更新账号及默认截图设置。真实用户数据导入与原生文件选择器仍需实机验收。

桌面新增“账号与应用组”页面，支持新增 / 编辑账号、设为当前账号、参与一条龙标记，以及应用组内启停和上下移动。界面显示配置修订；冲突后读取最新内容并提示重新编辑，不自动覆盖。浏览器预览没有本地配置，只有连接桌面引擎后才开放编辑。

### 命令行导入

源码环境可先在 PowerShell 预览，保存返回的 `preview_id`，退出使用目标数据目录的桌面 / 引擎后应用：

```powershell
cargo run --locked -p od-tools -- import-config --source E:\Code\ZenlessZoneZero-OneDragon --data E:\Code\zzz-auto\data
cargo run --locked -p od-tools -- import-config --source E:\Code\ZenlessZoneZero-OneDragon --data E:\Code\zzz-auto\data --apply --preview-id '<上次预览的64位指纹>'
```

将示例中的数据目录替换为实际目标目录。便携版使用程序目录下的 `data`；安装版和桌面开发模式使用 Tauri 的用户数据目录，当前 Windows 默认位置为 `%APPDATA%\io.onedragon.zzz-auto`。源码 CLI 的默认数据目录与桌面开发模式不同，不能因为在工程下运行工具就假定写入了桌面目录。`od-tools` 是源码开发工具，本轮未新增便携导入程序或重打包测试 ZIP。

首次导入前不要保存默认账号或通用设置：保存会建立正式配置，首批导入将拒绝覆盖它。已归档的原始 YAML 不自动参与游戏运行。当前应用组可以预检并试运行邮件，账号自动登录、其余配置字段转换及多应用执行属于后续工作；当前按日跳过只认带游戏日的新账号成功记录。

## 应用组管理

桌面支持在当前编辑账号内新建、复制、重命名和删除应用组。名称为 1..80 个字符；新组由引擎生成永久标识，重命名只改展示名称。旧配置没有名称时，默认组显示“一条龙”，其他组显示原标识。新建组包含默认应用且全部禁用；复制保留原组的应用顺序、启用值、未知应用及运行策略，之后分别编辑。运行预览显示组名，新运行记录保存启动时的组名，之后重命名或删除不改写历史；旧记录继续按原标识显示。

每个账号最多 64 组，至少保留一组。删除前在页面核对账号和组名并确认；保存仍先备份配置，删除不清理旧配置归档或账号历史。新建和复制采用新标识，删除后不复用。每日成功依旧按账号、应用和游戏日判断，复制或重命名不会清除已完成状态。现有自动备份可在同页预览并恢复，规则见[配置备份说明](config-backups.md)。

所有变更沿用统一修订号、文件锁及运行互斥；配置冲突后刷新并清除删除确认，不自动重试。切换账号、切换组、重新读取、断线或开始任务均清除删除确认。修改修订或选择组后，已有运行预览和输入确认失效，必须重新预览。损坏或缺失配置无法通过桌面读取时，可使用总览的[离线恢复入口](config-recovery.md#桌面恢复)，命令行继续可用。

协议升级至 v19，桌面与引擎须配套更新。账号文件仍为 schema 1，缺少名称的旧配置继续可读；包含新名称的文件需要当前版本读取。运行资源格式未变，schema 1 的协议 15..19 及 schema 2 的协议 16..19 包继续兼容。

## 账号复制 删除与排序

随后补齐账号配置复制、确认删除，以及账号和应用组排序。副本使用新编号，保留区服与完整编排，默认不参与一条龙；当前账号保持原值，凭据和历史不复制。当前账号和最后一个账号不能删除，删除保留历史、归档和编号，可通过备份找回。

引擎全部配置修改复用文件工作互斥，未保存结果及遗留输入也会拦截；界面冲突、运行、断线或切换选择撤销删除确认，排序后重新预览运行计划。协议升级为 v21，保留旧资源包兼容，账号文件结构不变；具体约束、试用和验证见[账号管理说明](instance-management.md)。
