## 藏品选择

纯决策输入是已经识别、去除同槽歧义的候选，使用稳定槽位编号；观察与执行见下方子流程。重复槽位和无效目录条目会拒绝决策。结果只返回槽位及原因，不包含跨帧点击坐标。

主选组整体先于次选组。每组内依次考虑 NEW（S / A / B / 其他）、动态规则、配置第一组、配置第二组、战斗追加规则、普通补位、动态放弃组补位。第一 / 第二组开关分别控制前两级和后两级；只有四组规则本来全部为空才强制允许补位，不能因为开关屏蔽了规则而购买其他藏品。NEW 要求方案和本次调用都允许。槽位升序作为同优先级顺序。

规则支持分类、名称、分类加名称、分类加 S / A / B；兼容分类标点和“击破 / 异常·击破”，采用明确名称匹配。旧版的任意子串分类与 0.6 模糊名称匹配未迁移，避免错误类别或错字直接形成后续消费依据。目录来自参考 YAML，生成工具同时记录来源 SHA-256；运行时不读取参考仓。

## 使用与验证

桌面“账号与应用组”中编辑迷失之地。展开“迷失之地挑战方案”可编辑全部方案字段；保存后其他组保持各自设置。配置缺少本模块时补默认值，存在但无效的配置仍报告错误。界面在运行中禁止修改，保存失败保留草稿，换组或读取新修订后重新载入。

```powershell
cargo run --locked -p od-tools -- lost-void-catalog --reference E:/Code/ZenlessZoneZero-OneDragon
cargo run --locked -p zzz-engine -- lost-void-preview
cargo run --locked -p zzz-engine -- lost-void-preview --input resources/lost-void/preview.example.json
```

预览 JSON 可包含 `config`、`candidates`、`count`、`options`、`day` 和 `history`。省略配置采用新版默认值；省略候选只展示配置。每个候选须包含 `slot`（0..31）、目录中的 `category` / `name` / `level`、`is_new` 和 `is_primary`。候选不是原始 OCR：调用者须先解决同槽歧义。`options` 可控制 `priority_1`、`priority_2`、`fallback`、`new_first`、`dynamic_priority`、`battle_priority`、`abandon` 和 `ignored_slots`。默认允许两组优先级、普通补位和 NEW；NEW 同时受方案开关约束。

提供区服游戏日 `day` 才计算日 / 周计划；`history.day` 绑定历史计数和奖励标记，跨日重置每日次数，跨 ISO 周或区服不复用周结果，未来记录拒绝采用。该接口仅作决策演示，手工输入的标记不是生产完成证明。CLI 不加载 SDK，不连接窗口，也不写入配置、周记录或每日记录，始终返回 `executable=false`。

协议升级为 v54，导入预览保持 v21。原执行资源和输入恢复版本保持原义。目录生成后须重新编译 Rust；桌面与引擎须成套更新。

## 入口与画面推进

完整应用共用 `LostVoidObservation` 同帧观察和独立 schema 1 `lost-void-scene` 资源。场景分类包含常规 / 周期入口、三类副本、矩阵编队教学、通用选择、武备、商店、抽奖、路径迭换、结算和失败；悬赏只接受完整且唯一的 `当前值/8000`，缺字、冲突及超出上限都保持未知。当前固定 254 份参考来源记录，另有加载标识、完整奖励格及普通出战人数三份本地来源元信息，包含 OCR、模板掩码及 87 个代理人头像变体；生成包共 107 个文件。所有 Pipeline 节点均只读，输入由 Rust 子流程控制。来源增加或节点变化后必须重新生成，旧生成目录不能直接复用。

`lost-void-scene-bundle` 默认从本仓留档生成模板和识别规则，并按 `models.lock.json` 校验 OCR 缓存；桌面准备脚本使用此模式。清单中的 `sources` 保留迁移时的历史依据，不要求开发者当前参考仓仍包含相同 Python 文件。显式传入 `--reference <目录>` 时，额外严格核对全部历史来源、奖励原图与头像原图；该模式用于迁移来源审计，参考仓有改动或缺失文件时仍拒绝生成。两种模式的包内容及运行时逐文件校验保持一致。

入口子流程冻结运行 UUID、完整配置和活动预算。从大世界经作战手册，按目录中的“周期征讨”或旧“零号空洞”分类同帧配对“迷失之地”与前往按钮；选中分类须有本行蓝底证明。打开手册、切页、选分类、有界滚动、传送确认、入口切页和副本选择分别保存意图与投递结果。新帧才确认后态，不能用点击完成提供到达证明。已有入口或副本可以直接识别，已有传送弹窗需要本次意图才可确认。

入口提示沿用固定 `lost_void_entry.yml` 更新弹窗关闭区 `[1234,160,366,190]` 和 `menu/btn_close` 模板，要求同帧入口“周期 / 常规”和“探索收集”上下文，以及唯一且完整落在区域内的关闭图标。图文信息层不依赖未经证实的更新正文；悬赏标题、全部领取及更窄关闭区共同构成独立的悬赏面板类型。未知 X、多个关闭图标、决策或奖励控件均不能当作信息提示。当前没有可靠更新弹窗原图，此分支以明确标注的组合帧验证，保留实机兼容验收。

关闭只属于实际入口执行器：连续两次同类型观察后保存独立意图，输入前重读类型与位置；它保留原导航阶段、分类、滚动次数及待处理传送动作。已尝试或结果未知时不重发，明确未发送才允许重新观察。关闭后连续两张同一入口 / 副本新帧才恢复导航；暂停撤销帧计数并保留投递历史。关闭悬赏面板不点击领取，不构造奖励或通关证明。

本阶段交接副本详情或已满悬赏读数，不出战、不写日周次数。后续必须继续选择战略、增益和队伍，完成局内流程与结算；入口回执不能提供整场成功或执行权限。父子共用控制句柄和剩余活动预算，暂停后只重新读取页面；已投递输入不重放，半次滚动不算一次完整翻页，终态保存失败或输入未释放不能交回父流程。

## 局内选择与交互

### 出战准备父流程

内部准备父流程按入口回执分流：战线肃清和特遣调查先完成调查战略及增益，再准备普通队伍；矩阵行动直接准备主战与协战，沿用来源中不经过调查战略的路线。父流程在首次输入前冻结所有候选脚本、场景、普通选队和战斗资源；后续仅从冻结结果选择。全部子流程共用运行身份、控制句柄和父活动预算。首次入口输入前同时预检前台模式及切人绑定，复用实际队伍模块的组合键和导航冲突校验；这项纯配置检查不构造人数或名单证明。

`LostVoidPreparationRun` 串联全部准备子流程，`LostVoidDeployRun` 采用独立状态机。普通页只按完整“预备编队”与“出战”，矩阵页还须复验已选主战、协战、属性及白色可用的“开始挑战”。点击前后保存意图，只有本次出战意图才能接收“确定并出战”低等级确认；低等级按钮兼容完整“确定并出战 / 确定並出战”，固定按钮区与弹窗区须对应同一位置，不使用任意子串。未知确认、仓库容量和失败 / 结算均不能作为到达。连续两张新帧看到迷失之地大世界、初始武备、事件或明确的局内选择页后才交回实际页面。输入未知或暂停恢复不重发出战。

普通预备编队人数来自实际槽位回执；保持当前队伍则读取出战页右上完整计数分母，经连续两帧和点击前复核冻结实际一至三人。缺失、冲突或零人不出战，不能用 HUD 漏识别或默认三人代替。矩阵人数来自三名主战回执，协战不计入主战。少人确认只接受本次已发起的一至二人出战，正文须明确队伍人数不足及继续出战的询问，并排除支付、领取、退出或低等级用途；与低等级确认分别保存一次性意图。当前少人正文使用标注组合帧验证，尚不能断言实机文案兼容。

### 通用选择

通用选择实现鸣徽、卡牌和获得物确认。观察从名称区读取目录中唯一匹配的名称，将 NEW、已选择和同流派限制按本列配对；不接受任意描述文字作为藏品。同流派只作为不可选限制，不计入已选数。槽位由本帧从左到右排列，检查点冻结完整候选身份，点击前再次核对；动态坐标不保存。双选必须读取完整计数，单选缺计数时使用已选择标记或白色可用确认按钮，并核对已投递动作及候选未变，不能拿点击次数充当选择数量。

名称区覆盖旧版较高的武备名称和较低的无详情名称。对首字漏识别进行单行复读，规范中文引号与方括号；仍须完整匹配目录，不以模糊错字创建候选。无标题领奖只在单个已知藏品、无计数且白色确认同时出现时允许确认。NEW 在选中后消失不会改变藏品身份。战术棱镜通过本列 a / b 图标绑定分支身份；两列必须属于同一基础武备，缺少或冲突时不操作。

父流程冻结运行 UUID、交互 UUID、挑战方案、动态优先级和允许返回的局内页面。每次只点一个候选，先保存意图，再保存投递结果，等待新帧的选择后态才继续。已投递或原生异常留下的意图都不重放；出现未知弹窗、候选变化或计数冲突时不继续输入。确认后必须观察到允许的返回页面才交回父流程，获得物页面可以连续确认，但同一内容不重复确认。回执只证明本次交互离开选择页，不是挑战成功或次数证明。

暂停、停止、活动预算、输入释放和保存失败处理沿用入口子流程约束。原图 OCR 与隔离控制器组成完整选择测试，合成已选后态单独注明，实机验收继续保留。

执行器是 `zzz_engine::lost_void_choice::LostVoidChoiceRun`。父任务须提供运行 UUID、交互 UUID、冻结方案、动态优先级、允许返回的局内页面和剩余预算。最多连续处理 16 个不同的已知获得物页面。

### 抽奖及路径迭换

抽奖读取按钮完整的“开始 剩余/总数”，读不到保持未知；仅剩余为零才能按耗尽退出。每次抽奖单独保存意图及投递结果，等待次数减少或出现本次通用选择；动画期间、暂停恢复和输入异常都不能重抽。通用选择沿用同一父控制和活动预算，子回执必须属于本次交互并返回抽奖机，父流程再读新的剩余次数。抽奖后没有明确的选择页或次数后态时停止推进，不采用旧代码中近全屏的“确定”区域。

路径迭换沿用参考行为，只返回局内大世界，不消耗定位卡。抽奖与路径迭换均在确认事件页或大世界后回交，回执记录实际返回页面，已有大世界页面不能代替本次退出输入的后态；回执不能增加挑战或奖励次数。

执行器是 `zzz_engine::lost_void_interact::LostVoidInteractRun`。选择子流程开始前、执行中和刚完成时的暂停均由同一父控制处理；保存子流程意图失败会使父流程失败，不能退出为成功。没有迁移旧版近全屏的任意领奖按钮；未有明确来源的额外弹窗继续保持未知。

### 武备与棱镜

武备列表沿用固定底部区域、亮度过滤、两次三像素膨胀和连通区域检测，从左到右编号。每个槽位记录图标内部的身份摘要和是否已有等级；输入坐标只在本帧生成。正常携带前逐个查看名称并完整扫描两遍，每次等待两个稳定的新帧，第二遍须与第一遍该槽名称一致，多槽位时还须不同于此前显示的名称；不以点击成功代替槽位与名称的对应。每个查看动作保存意图。扫描期间列表身份变化、名称歧义或已投递动作后态缺失都不能继续携带。追新先从未获取武备中按方案排序，没有未获取武备时使用普通优先级。

父流程可以提供本层已完成的首槽名称。只有本次首槽明确匹配已完成项才判重；不使用其他槽位代替首槽。完成携带后，识别本次携带的明确确认弹窗、获得物子流程以及返回事件页或大世界；之后才回交首槽名称和所选武备分类，供父流程更新判重及战斗优先级。弹窗不改变“不再提示”设置。暂停后不重复携带和确认，不用输入成功代替返回证明。

通用选择中的战术棱镜从固定来源 a / b 图标配对本列，要求同一基础武备的两种不同分支都被识别，随后复用通用选择。不会把没有分支身份的基础名称当作 a 或 b。

### 商店

商品名称、当前价格和可用购买按钮按同列配对。硬币 / 血量商店由固定图标区分，缺失或冲突保持未知；硬币读取完整余额，血量读取冻结队伍人数对应的全部生命百分比。血量下限沿用原配置含义：达到下限才购买或刷新。未知价格、余额或成员血量不能提供消费依据。零号严选和普通货架分开记录身份，刷新不将严选变化当作普通货架刷新证明。

### 战略、周期增益与编队

`LostVoidStrategyRun` 对照 `lost_void_app.py` 的副本、调查战略与周期增益逻辑，战线肃清沿用游戏当前难度，选择配置战略及 1..3 周期增益；特遣调查先识别完整且无重复的三名本周 UP，选择战略后跳过周期增益。只在本次“下一步”之后看到出战页才交回，不发送出战或写挑战次数。父任务提供运行 UUID、冻结挑战方案、同一控制句柄和剩余活动预算。

追新沿用三条颜色 / 轮廓流水线，包括 HSV 色相回绕、矩形腐蚀膨胀和四像素核锚点。先选明确无等级圈，再选无满级数字轮廓的等级圈；最多三次完整左滑后回退到已知等级圈，缺少圈圈保持未知。正常模式按目录顺序决定滑动方向。名称与本帧槽位、圈圈按列配对，坐标不进检查点。半次拖动不消耗完整翻页次数。

战略列表连续两张新帧确认本次选择及可用“确定”。回执区分明确名称后态 `named` 与本次单选加可用确认 `own_pick_enabled`；现有原图的副本详情只显示调查战略图标，不显示所选战略名称，不能声称返回详情又读到了名称。确认后重新识别同一副本，周期增益必须先识别三个有效绿色圆环，点击后只允许目标圆环中心出现单选标记；读不到或多选冲突不继续。战略列表和选中增益后态暂用明确组合帧验证，实机后态继续待验收。

### 首次输入前的战斗准备

`FrozenLostVoidPreparation` 保存本次运行 UUID、副本、挑战方案、二十槽编队、账号战斗设置、脚本修订及本周 UP 完成状态。沿用 `PreparedDeployment` 编译候选脚本及全部引用，逐个校验战斗识别定义和输入设置。所有候选须在第一次游戏输入之前编译完成，任何可能用到的脚本缺失或修订变化都使预检失败；后续只克隆内存中的编译结果，运行期间切换导入选择不会改写已冻结指令。完整战斗和零启动延时由应用准备统一设置，其他按键、设备、合并模式和帧龄参数保留冻结值。

候选编队与候选脚本共用同一次 UP 组合决策，保留配置回退与全部可能胜出的槽位。固定手选或已知编队要求相应代理人的战斗资源；保持当前或任一候选含 unknown 时，要求完整目录的代理人资源，不能用 unknown 代替身份检查。矩阵协战仍独立于主战，不插入战斗队伍。计划解析后必须与冻结配置重新计算的结果完全一致，实际主战名单只接受完整目录中的唯一身份，并按已配置的位置核对；这里只校验传入名单，实际截图证明仍由部署 / 战斗父流程提供。

战斗清单及每个文件在载入和后续交接时复验，修改清单、模板、模型或脚本包都会撤销交接能力。场景与普通选队所需日常包单独冻结并复验，普通模式要求 schema 10，矩阵模式不依赖普通列表资源。`with_npc_detector` 可在首次输入前扩展固定迷失之地 YOLO 模型及标签依赖，并在交接时复验字节。这不代表完整挑战已具备首次输入资格；完整父流程仍须把后续导航、移动、结算等依赖全部纳入预检后才能开放。

真实画面、暂停停止、异常收尾、长时间运行及全部实机验收继续保留。

### NPC 交互记录与返回后移动

`NpcMemory` 保存运行 UUID、楼层 UUID、本次交互 UUID 和明确目标，向层流程提供能否交互的判断。NPC 名称、目录代理人名称及入口完整匹配，不采用任意子串或模糊名称。已完成对象不再提供按 F 的许可；未知文字也不提供许可，导航须调整站位重新读取。进入新楼层建立新的记录，不能跨层复用已交互名单。记录模块不发送 F，实际名牌读取及许可应用由下述导航执行器完成。

事件返回后，以同运行和交互 UUID 的事件回执更新记录；初始大世界、未知页面、错 UUID 或单个对话动作均不能代替完成回执。记录保留已完成武备首槽及重复次数，入口重复三次后跳过感叹号。交接后先完成对应移动，再允许开始下一次交互。记录和移动回执是层内推进，不写挑战成功或日周次数。

返回后移动沿用原 NPC 规则：研究员向右；首次奥菲莉亚按新帧中是否仍有感叹号选择前进后左移或后退；入口其他武备交互后后退以露出相邻目标，已放弃感叹号时向前脱离；挚交会谈按代理人或 NPC 方向绕过桌子，其余后退。战斗后交互不额外移动。每个方向独立保存意图和实际持有时长，暂停后只完成剩余时长，未知投递不重放。每段输入前重读大世界，受同一父控制、剩余预算、前台与 1500ms 新帧检查约束；恢复后重新验证，最终连续读取两帧并确认释放输入才交回。

奥菲莉亚的分支复用已固定的原 YOLO 模型和头像遮罩，空结果与未完成推理分开；未知不视为没有感叹号。首次移动前图标变化时，明确未投递才可重新选择分支；已有部分持有或未知投递不改变原意图。NPC 移动额外阻断单独“确认 / 确定 / 取消”按钮，避免没有取消按钮的未知遮罩露出底层大世界而放行方向键。

`LostVoidNpcRun::after_event` 只接受已保存并释放输入的实际事件执行器回执，验证同一父控制、运行与交互身份；返回移动完成后才由父流程接收并解锁下一次交互。匿名对象仅用于已经自动弹出的交互，不提供按 F 的许可。已完成武备首槽必须是目录中的唯一有效武备并保持之前记录，不能在下一次回执中删除。

锁定入口后却完成非空事件并返回当前世界时，按途中匿名交互记录；不消耗该入口，也不提供下一层证明。实际换层仍须由层流程观察转换及新区域后确认。

只读 `lost-void-scene-inspect --npc` 检查世界页面及当前帧是否仍有感叹号，与其他详细开关互斥；输入始终为 false，模型来自当前资源目录下的固定 recognition 包。玛琳原图的实际 YOLO 正例为“偶遇事件”，在本模块属于其他类别负例。感叹号存在分支已做核心决策测试，但仍缺真实感叹号正例，不能把该图或组合后态冒充这一分支的实拍。新增 NPC 名称定义来源后总来源为 229 份，独立 schema 1 须重新生成。

### YOLO 导航与交互提交

导航冻结楼层记录、区域优先级、忽略类别、总预算及转向参数。检测只接受固定模型的完整 16 类，保持原 0.6 / 0.5 阈值与头像遮罩。感叹号、距离、入口分开；相邻入口按原距离规则合并为连通组，单入口先于混合入口，按配置优先级及最右位置选取，持续跟踪同类型组中位置最近者。奥菲莉亚完成后的道中危机排除和入口全部 NPC 已完成后的感叹号跳过沿用原规则。

转向使用原屏幕中心死区、首次小幅试探、实际反馈校准和过冲抑制；输入意图保存前不把计算值当作已经转动。每段移动及转向重新截图验证目标，保存的矩形仅用于跟踪，不能作为跨帧输入坐标。丢失图标重新识别，不能单凭消失声明到达。背景运动检查和有界脱困已接入同一导航状态机，不能把图标位置抖动当成角色前进。

交互按钮出现时读取完整名牌，仅唯一目录对象且获得当前楼层许可才按 F。已完成对象或未知名牌先按剩余图标调整站位；不迁移未知文字重试到上限就盲按 F 的兜底。F 的已提交、未知投递和后续页面分别保存，暂停后不重复。导航只交回提交或观察结果，不写 NPC 完成、下一层到达、挑战成功和日周次数；后续事件、换层或战斗由父流程继续验证。

`LostVoidNavigationRun` 共用父控制、剩余活动预算和保存回调。前进与调整站位暂停后释放输入，并从新帧闭环计算；已投递 F 保留，不重复按键。已观察事件页可通过 `event_request` 交给同身份事件执行器，再由 `LostVoidNpcRun::after_event` 登记和返回移动。未知 F 后自动弹出的事件只取得匿名所有权，不能猜测是谁完成交互。入口名字仅交回区域提示，不构成换层证明。

战斗提示、Boss 血条及明确闪光可让导航交回战斗观察；普通攻击按钮本身不构成战斗证明。未知居中弹窗和过期截图阻断输入。所有退出路径确认释放输入，意图保存失败、迟到暂停停止、父预算耗尽或释放失败均不提供成功回执。

只读 `--navigation` 同帧输出世界、固定模型检测、交互按钮、战斗标记和唯一名牌，与其他详细开关互斥。玛琳原图实际识别出“玛琳”、交互键及偶遇事件图标；前进、F、对白和返回连续后态使用标注组合帧及隔离 Maa 控制器，未操作游戏。来源新增导航和检测器定义后为 231 份，87 个头像变体不变。背景运动与脱困见下文；下一层到达及完整战斗父流程继续开发，全部实机验收保留。

### 背景运动与脱困

对照 `lost_void_motion.py`、`lost_void_navigation_config.py`、`lost_void_move_by_det.py` 及原大世界四个移动检测区域。背景只在固定镜头、方向键实际持有期间比较；每区灰度化、面积缩至 96×64、三像素高斯模糊，去整体亮度差，以纹理标准差、变化像素占比和多个区域 / 样本投票判定。低纹理、采样不足、倒退时间或长间隔不能当作卡住。画面、镜头或暂停变化撤销旧样本，不把检测框移动当作背景运动。

正常前进累计三秒安排固定镜头探测；按原 300ms 最小间隔采样，至少观察 1.5 秒，未知最多延长至 3.9 秒。探测中每张新帧检查世界、交互及明确战斗；页面变化即释放方向键并返回导航重读。未知只表示观测不足，正常探测未知不增加受阻次数。所有探测服从父剩余预算和控制，不另起运行或持有权。

确认静止或连续丢失目标后开始有界脱困。已冻结普通攻击绑定且新帧按钮可用时，仅尝试一次清障攻击；没有绑定时先绕行，不猜按键。左、右、左后、右后、后按失败较少且避免立即重复的顺序探测；侧向确认可移动后再探测前进，前方仍静止时同侧最多三次。受阻过程最多十二次，未知侧向结果不能记为成功。镜头累计转动二百清除旧相对方向，正常前进确认成功才清空受阻过程。暂停保留次数和未知攻击意图，释放所有方向 / 鼠标；恢复重新采样。

原“切换最适合移动的代理人”依赖实际战斗名册，后续接入真实成员证明后实现，本阶段不按配置名单猜切人。背景运动结果只用于局内导航，不提供位置、换层、战斗或挑战完成证明。

`MotionDetector` 使用参考示例默认参数：灰度差大于 10、变化占比至少 0.08、纹理标准差至少 3；每次比较至少两块有效区域，至少两次有效比较且三分之二投票一致才判断。`MotionRecovery` 保存次数、方向失败和一次清障状态，不保存像素或旧截图。正常探测未知不增加次数，未知绕行也不能证明已脱困。暂停后清除相对方向记忆，保留次数及清障提交状态并重采样。

`NavFlow` / `LostVoidNavigationRun::with_obstacle_attack` 可在第一次输入前接收父任务已冻结的单个键鼠普通攻击绑定；与 WASD、F、Alt 或 Esc 冲突时拒绝，不存在绑定时仅作方向探测。探测不会转动镜头。每个方向键投递前复核预算、取消和原新帧年龄，避免第一笔原生任务阻塞后再用过期画面发送第二个方向。输入失败或释放失败不提供运动结果，父任务仍沿用共享预算及保存语义。

### 实际队伍与移动代理人

对照 `auto_battle_agent_context.py`、`auto_battle_utils.py`、`lost_void_run_level.py::append_agent_type_priority`、`battle.yml` 和实际玛琳原图。原图是三个紧凑头像，不能直接使用通用战斗识别器的固定前台 / 后台槽位。新读取在已有头像区域的顶部并集内同时匹配前台及后台固定模板，沿用 0.8 阈值和掩码，按空间分组及得分取唯一身份，完整核对父任务从出战页取得的 1..3 人数。未识别后台不能当作人数减少。初次完整目录发现可较慢，输入前须重新截图并验证每张已识别头像的实际有效像素；变化时重新发现，不能用旧截图操作。

父任务冻结运行、楼层、选队计划、完整人数、挑战方案、动态规则及实际切人绑定。HUD 按当前前台排序，已知出战顺序只允许循环轮换；保持当前及 unknown 仍要求完整且唯一的实际目录成员。连续两张新帧确认后，按原身高 / 速度规则选最适合移动者；已在前台就不切。否则只投递一笔最短的上 / 下一个切人，先保存意图，再确认完整轮换后态；原顺序、错队伍、未知及动画不证明切人成功，暂停及未知投递不重试。切人不能代替编队或 UP 通关证明。

动态优先级采用实际成员在冻结战斗资源中的类型，保留已有武备及配置规则。只采用当前藏品目录实际存在的分类；“异常 / 击破”共享完整“异常·击破”分类，任一类型在队伍里就不能把共享分类放弃。缺席分类仅在没有具体名称 / 等级保护时加入动态放弃组；新规则仍遵守主次组、NEW 和既有选择顺序，不创建当前目录不存在的类别。返回回执须保存、释放输入且控制与预算正常，冻结准备在后续交接时再次验证身份和资源。

此步骤在迷失之地大世界取得实际成员及移动前台，完整战斗父流程仍须接通；通用战斗识别器对紧凑 HUD 的能量 / 技能等位置也需随实际战斗交接核对，不能把本步骤当作所有战斗状态已验收。

`LostVoidHudReader` 的目录发现覆盖前台 / 后台两套固定头像，重叠命中按同代理人最高得分归并，不同身份同分保持未知。只缓存实际匹配头像掩码内的像素摘要，输入前重读世界和全部摘要；变化时拒绝旧输入并重新发现。发现耗时不放宽 1500ms 输入帧龄，取消、未知画面或暂停也不能沿用旧稳定读数。原图已读出叶瞬光、千夏、照，按原优先级应切至千夏。

`RosterFlow` / `LostVoidRosterRun` 冻结切人方向键鼠绑定，支持组合键；部分组合输入、未知投递和原顺序都不重试，须看到完整预期轮换。`FrozenLostVoidPreparation::roster_request` 从已冻结设置生成请求，`create_roster_run` 拒绝更换方案或绑定；`create_segment_after_roster` 只接受本次执行器已安全交回的同控制回执，再核对目录身份、类型及资源。此交接仍只创建已编译的子战斗，不提供战斗完成证明。

终态保存期间的耗时继续计入活动预算，保存期间迟到的暂停 / 停止会撤销回交能力；恢复须重新取得两张完整新帧，已完成的切人不会因此重放。保存失败和释放失败均不提供回执。普通出战页人数的自动读取仍随完整出战父流程接入，不能由本模块把识别到的头像数量当作人数证明。

当前代理人目录为 61 人。原默认战斗包只有 60 人，缺少菲欧妮，“保持当前”与未知成员的完整预检因此正确拒绝。已从固定来源重建 61 人战斗包，按完整身份与类型集合验证；替换时保留旧包在 `artifacts/lost-void-roster-combat-backup-60`，没有把预检缩成已知三人。日常默认 schema 7 不变。只读 `lost-void-scene-inspect --roster` 提供原图 HUD 与候选匹配诊断，与其他详细开关互斥，始终不发送输入。


## 完整层流程后续设计

准备父回执只确定初始局内页面，后续层流程已按下方设计接入。初始武备 / 通用选择交给已有子流程，实际队伍与移动前台必须等大世界完整 HUD 确认后建立；事件请求的血量商店人数仍须使用实际出战人数，不能为保持当前方案填三人。矩阵协战属性并入既有战斗追加规则，协战不当作第四名主战。

`CombatRun::execute_segment_guarded_with_budget` 已补充每帧继续、等待及交回守卫，迷失之地专用 `LostVoidBattleRun` 使用外部页面边界，普通结算入口保持原语义。冻结准备只从同控制、同层的实际队伍与导航执行器构造局内战斗；先结束推理与调度并释放输入，再交回明确页面、探索或阵亡回执，不暂停整个父控制来模拟正常脱战。出战时的紧凑 HUD 队伍回执不能充当战斗能量、技能、生命区域正确的证明，守卫另行复验正常战斗 HUD 布局及完整主战身份；只有普通攻击图标不构成遭遇证据。完整层父流程仍须串联此执行器及后续页面处理。

导航 F 意图、门牌或“前往下一个区域”提示不能直接生成新层身份。跨层须绑定本次出口意图及实际离开 / 到达后态，再重建 NPC 记忆、目标跟踪和移动观测；未知黑帧不能单独当作加载。挑战结果须区分精英的确定与整场完成，结算保存与奖励领取属于外层任务。参考旧版以“未识别到业绩 / 丁尼”推导奖励耗尽的做法不能作为新持久化证明，继续要求明确的奖励或已领 / 耗尽证据。


### 局内战斗交接实现设计

扩展通用战斗段的每帧守卫，保持既有普通结算接口。守卫返回继续、等待或交回：等待与交回都释放已按住输入、清空动作队列并撤销旧状态；定时松键仍优先于下一次截图。迷失之地使用外部页面边界，关闭普通战斗“完成 / 撤退”推断；边界原因由本次局内状态机保存，不用暂停父控制模拟正常脱战。守卫在识别与动作调度之前运行，新的按下仍受原战斗帧龄限制。交回后及终态保存期间的暂停、停止、预算耗尽和释放失败都撤销安全回执。

同次战斗短暂重读另有 `Refresh` 分支，同样松键、撤销未完成动作、旧视觉 / 按键状态及音频，保留已经提交的 `自定义-` 状态和场景冷却。它用于头像切换或发现耗时后的新帧复核，避免每次合法切人都重置脚本计数；恢复后只能由新视觉状态再次触发动作。明确页面、未知页面、确认弹窗及用户暂停沿用完整清空，未执行的自定义动作不保留。

正常战斗 HUD 在来源固定的前台大头像和 1 / 2 个后台小头像位置完整匹配本次实际主战，拒绝紧凑大世界 HUD 或部分识别的成员数。按实际 1..3 人数选择对应区域，身份只来自冻结战斗目录；同分歧义、成员变化或角色切换动画保持未知。头像布局锚定后才采用同版定义的生命、能量和技能区域。`BattleFlow` 绑定本次导航遭遇证据，正常 HUD 连续两次确认才开放输入；明确事件 / 武备 / 选择 / 结算 / 失败页连续三次，阵亡及下一地区提示两次，F 三次，非首领十份不同高置信度 YOLO 结果才形成对应交接。普通攻击图标不能独立开放战斗输入，换层与整场成功继续由外层确认。

专用战斗执行器由冻结准备接收同控制的实际队伍及导航执行器，核对运行、层、方案、区域和遭遇回执后构造；调用方不能直接用配置名单构造生产交接。帧守卫优先复核当前正常 HUD、普攻 / 连携、阵亡、F 及确认弹窗；头像或页面变化先返回等待，待通用战斗释放输入后的下一张新帧再作完整页面读取。HUD 仍完整时的周期探测仅作同帧只读 OCR / YOLO，不为探测本身重置脚本自定义状态；它仍计入原新帧及活动预算，耗时超限就撤销输入许可。非首领沿用来源 0.8 秒探测、出现目标后 0.1 秒复核，十份不同高置信度结果才交回探索；重复缓存不计票。深读或身份发现耗时导致旧帧时只缓存发现结果，下一张新帧复验后才开放输入。守卫不点击确认。

状态机、活动时长及通用战斗进度一并发布。交接终态保存、资源复验或输入释放失败不提供回执；迟到的暂停 / 停止 / 预算耗尽覆盖正常交回。恢复清除头像缓存及稳定计数，保留探测序号以拒绝旧结果，重新取得实际新帧。该执行器仅报告本次战斗返回页面、探索或阵亡，层循环和外层结算继续接入。

### 层循环与跨层交接

层执行器从准备的实际局内页面开始，先处理自动弹出的初始武备 / 选择，再取得完整实际队伍及移动前台；之后循环导航、战斗、事件和 NPC 返回移动。层内只有一份 NPC 记忆、选择追加规则及活动预算，子执行器共享控制，回执保存与输入释放正常后才推进父阶段。矩阵协战属性进入选择追加规则，人数仍取三名主战；普通人数必须来自出战证明，保持当前队伍未知人数不能补成三人。

导航的门牌和 F 提交只保留出口意图。跨层另外读取明确加载观察，并要求到达后的两张新帧均为迷失之地世界及完整原队伍。`loading.yml` 的 NOW LOADING 仅作为识别到该标记时的证据，不假设所有迷失之地过渡都显示它；留档 lore 加载图没有此文字，且 UID 已打码，改为组合左侧 HOLLOW 标识、括号标题、多行正文、低饱和度及右侧场景纹理，世界 HUD 不在场。沿用 `enter_game.py` 的低饱和度来源并排除其允许的全黑帧，不把随机 lore 内容作固定文本。普通黑帧、菜单消失、仅 UID、仅文本提示和奖励弹窗都不算加载。此识别只附加到导航 / 事件观察，不改变既有全局画面分类。

加载记录只在本次已投递或结果未知的进门意图之后形成，并随该交互身份保存；明确未投递会撤销意图。导航和事件遇到加载时不点击，不提前完成事件。暂停保留已经发生的加载历史，撤销到达稳定计数，继续后重新核对实际世界和完整队伍；结果未知的 F 不重发。若门被事件抢占，就先处理同次事件；只有出口身份仍匹配且出现明确加载，才可交接新层。已经保存的新层身份在暂停后保持不变，不能再次分配一个 UUID。

挑战入口可能以明确的挑战开始确认代替可见加载：只接受本次挑战门牌、事件执行器实际确认的挑战目的文本，以及返回后的完整世界队伍，不把通用确认框当作开战。门内事件执行期间启用绑定出口身份的只读加载记录，覆盖选择 / 武备 / 商店等子执行器自己的截图；只在本次作用域采集，结束、错误和展开栈时都清理记录，避免子流程吞掉短暂加载。再次出现同次自动事件时继续原事件执行器，保留已消费选项与花费意图；没有加载或挑战开始证明的普通 NPC 事件返回原层走位，不分配新层。

下一层实际到达后交回目标区域和新层身份，由挑战父流程创建新的 NPC 记忆、导航跟踪和移动观测；当前层的武备重复与 NPC 访问记录不沿用。明确挑战结果 / 失败页和阵亡交回外层处理，层循环本身不记整场通关、奖励或日周进度。整场结算、恢复、普通未知人数来源及正式入口继续纳入完整迷失之地目标。

队伍复核与 NPC 走位可向层父流程交回连续确认的局内内容页；默认独立接口行为不变。自动弹窗处理后继续原执行器，保留已经投递的切人与已走距离，不能重新创建来重放未知输入。走位期间的附加奖励单独记录为当前移动中的自动事件，更新武备与选择规则，不提前完成原 NPC 走位。

内部 `LostVoidLevelRun::after_preparation` 只接收同控制的实际完整准备执行器；下一层通过 `after_transition` / `next_level` 消费实际跨层执行器。调用方不能直接传一份配置名单或伪造到达回执开始生产层流程。父阶段为队伍、导航、战斗、事件、返回移动和跨层等待；每次交接先核对实际子回执，资源、控制、保存和剩余预算正常才交给后继。跨层等待里的同次自动事件沿用原事件执行器，原层事件才交给 NPC 返回移动。

层内再次复核队伍时保留新武备追加规则；如果新规则具名保护了某个缺席分类，必须同时撤销上一轮自动产生的该分类放弃规则，不能只阻止再次添加。其他分类及补位、NEW、忽略槽位等参数继续沿用冻结值。

`NextLevel` 仅表示本次出口后的实际到达，`ObservedResult` 仅表示读到了挑战结果 / 失败页，`AgentDead` 交回实际战斗的阵亡判断；这三类回执都不直接修改日周记录。父任务最终保存时收到暂停，会回到产生该回执的实际子执行器重新确认新帧，保留已经预留的新层 ID；停止、保存失败、资源变化、超时或输入释放失败不提供可消费的完成回执。层快照目前用于内部发布，尚未提供跨进程恢复登记，正式任务入口仍保持未实现。

### 整场结算设计

挑战结果页包含无按钮奖励展示、确定和完成三种子态。来源 `lost_void_run_level.py::handle_challenge_result_confirm` 在确定后交接挚交会谈；这只是中途首领结算，不能计为整场通关。内部 `LostVoidSettlementRun::after_level` 消费同控制的实际层执行器，保存确定意图，并在完整新帧世界队伍返回后创建挚交会谈的新层。完成按钮则须保存奖励观察及本次完成意图，连续核对实际返回迷失之地入口，才交回最终结束。

失败 / 主动退出的来源必须单独保留；来源实现的失败分支同样返回 `STATUS_COMPLETE`，Rust 父流程不能据此写入通关或 UP 完成。最终通关候选需要本次终结之役的实际战斗 HUD 和结果页交接；只有结果页而没有该战斗来源时，允许安全返回，但保留无法归因的结束，不能记通关。失败页撤退、阵亡及后续退出始终覆盖通关候选。

结算状态机接收当前层实际回执、冻结计划与人数。确定 / 完成 / 撤退分别保存独立意图，投递未知时不重发，明确未投递才撤销。中途确定后要求两张完整世界队伍，并交回预留的挚交会谈新层身份；完成后只接受两张常规 / 周期入口，不以黑帧、单个按钮消失或普通大世界代替。暂停保留已发生的输入与奖励历史，撤销新帧计数，继续后重新确认后态。保存、预算、停止和输入释放继续守卫实际回执。

奖励模板沿用固定 `hollow/challenge_reward_eval` 和 `critical_reward_money`。最终页须同时出现阴影结晶数据区域和完整 4×2 奖励格；每格应有明确数量或 EMPTY，完整格之外的数字不能补位。至少三份新帧并跨越一秒的完整格观察后才允许依据未出现的模板判断周上限，正向出现则保留历史。最多等待五秒奖励采样，仍不足时可以结束本次挑战，但周上限保持未知。完成输入前冻结该奖励证据，暂停或投递未知后不能借另一页改写它。中途结果与失败退出不更新周上限。

内部 `LostVoidChallengeRun` 顺序消费准备、层循环与结算的实际执行器，共用控制、运行 ID 和总活动预算；准备输入前必须已经冻结导航资源。中途确定及普通跨层均创建新层记忆，最终结束交回单次挑战结果。已满悬赏的实际入口回执直接交回跳过，不开始局内层。父流程 Ready 表示安全交回，调用方仍须区分完成、战败、无法归因和悬赏已满。日周目标、悬赏领取、幂等写入及跨进程恢复继续由外层应用处理，不提前归入当前层执行器。

### 日周记账与恢复

来源 `lost_void_run_record.py` 的次数和奖励标记按账号共用，应用组仅选择各自的计划目标。新版沿用已有 `GameDay` 的区服游戏日与 ISO 周语义；同账号不同组的挑战不能重复建立独立周额度。旧导入标记仍只归档，不参与新版完成证明。

生产记账入口只消费同控制且安全交回的单次挑战执行器。通关次数只来自 `Finished` 中明确的 `Completed`；战败、无法归因、已满悬赏跳过及中途挚交会谈均不增加次数。不能将 Ready、点击完成或返回入口单独当作通关依据。UP 完成还须绑定本次完整三名 UP 读数与实际终结战主战队伍；选队意图、矩阵协战及配置中的代理人名单不能代替实际成员证明，跨周时不能沿用旧 UP 读数。

最终结算的业绩点 / 周期上限分别按可选布尔值合并，未知不覆盖已知；实际悬赏读数只有完整 `8000/8000` 才能提供已满证明，领取仍是后续独立输入流程。完成时的区服游戏日须随提交证据保存，跨日或进程恢复时不能把旧挑战重新计入恢复当天；旧周证据也不能覆盖新周状态。

每场采用稳定的运行、层及结算 UUID 去重，重放同一提交不增加计数，内容冲突报告错误。先保存可复验的完成证据，再原子提交账号记录，保存失败保留同一待提交身份。恢复阶段只重放记账，不能据序列化快照重新产生游戏输入；游戏流程的继续资格需要另行验证实际执行器与新帧。此内部持久化入口已接入内部应用循环，正式运行入口仍待接入。

日周记录核心按账号保存本次结算的紧凑证据，并由实际完成游戏日计算计数，避免跨日恢复时修改当前日或当前周。紧凑证据保留层结果、结算身份、结束类型、奖励上限及悬赏读数，省略与记账无关的藏品规则；只从已验证的最终结算状态机提取，中途挚交会谈不能加入。相同结算内容幂等，同一尝试出现另一个结算身份或同 ID 内容变化时拒绝。周上限只向已达到合并，未知不覆盖已知。UP 完成需完整读到本周三名 UP，且实际完整最终战队伍中至少有一名 UP；三名 UP 不必全部上场。矩阵协战不纳入特遣 UP 完成，跨周的读帧区间也不采用。

持久化按账号、区服与 ISO 周保存，应用组不建立另一份周额度。每次先写独立的待提交结算文件，再原子替换周记录，最后清除待提交文件；崩溃后只幂等重放记账，不能投递游戏输入。目录锁保护并发提交，文件和目录拒绝联接；损坏、身份冲突、版本或容量不兼容时保留原文件并报告错误。完成时刻取实际最终结算确认入口的时刻，迟到暂停后不改成继续当天；账号与区服必须在准备输入前冻结，不能在结束时改记其他账号。

### 悬赏领取与最终返回

悬赏领取独立于挑战计数。领取状态机只在完整悬赏面板中采用明确可用或不可用的领取状态；面板消失、按钮漏读和任意弹窗都不算已领取。无可领取状态至少稳定一秒、连续两张新帧才可关闭面板；领取后出现的明确奖励弹窗只在本次领取意图之后处理，随后仍须确认面板已无可领取内容。投递未知时保留意图，不重复全部领取。关闭后通过已知入口或手册返回，连续确认普通大世界才交回；迷失之地局内大世界不能代替最终返回。

原生观察按固定悬赏入口、全部领取及关闭区域读取，同帧面板标题、关闭图标和完整按钮文字共同确认面板；白字与灰字分别提供明确可用 / 不可用状态，两者冲突仍为未知。领取后的“获得”或“获得道具”标题与固定可用“确认”共同识别奖励页，只有本次领取意图才能处理该页。`LostVoidBountyRun` 冻结场景根目录和资源清单，输入前、终态保存前后复验；暂停不重复打开、领取、确认或返回。新增原生五项及共享十五项全部通过，严格 Clippy、原生构建、格式、两仓差异及资源校验通过，证据为 `artifacts/lost-void-bounty-verification.json`。面板没有留档原图，组合帧只验证固定区域与执行协议，正式领奖应用入口尚待接入。

领取完成的内部持久化已接入并通过离线验证。`LostVoidBountyRun::with_record_context` 在首次观察前冻结账号、区服及本次处理的结算 UUID 集合；`claim_record` 只从本进程实际安全交回的执行器提取紧凑证据，暂停、未完成或缺少上下文时拒绝。首次普通大世界确认时刻在终态暂停后保持不变；悬赏读帧区间跨周，或与该完成游戏周不同，不产生新周已满证明。原始读数可以保留，不会借完成日期重新归属。新增十四项核心及共享三十四项通过，严格检查和原生构建通过，证据为 `artifacts/lost-void-claim-record-verification.json`。

`LostVoidRecordStore::pending_claims` 由当前周结算减去已完成领取批次，只读派生待领取；`acknowledge_claim` 使用既有目录锁和原子写入，将独立完成证据保存到 `runs/lost-void/claims/{claim_id}.json`，不增加或重新计算挑战次数。绑定集合最多 8192 个 UUID，独立领取文件上限 512 KiB；同 ID 内容变化、错账号 / 游戏周、完成日早于其绑定结算、损坏或版本不兼容均拒绝。延迟提交仍写原完成日，只处理原批次，较新的无关结算不阻止提交且继续待领取。没有挑战的实际已满悬赏检查可独立更新同账号 / 区服 / 周的进度，不伪造挑战结算。

### 应用循环与待领取恢复

完整应用先恢复待提交记账，再按账号和当前区服游戏日读取日周进度，决定继续挑战还是只处理领取。每次真实最终结算须先持久化原结算证据及其待领取标记，才更新账号周记录；不能在计数已经达标后跳过领取。待领取状态与具体账号、区服、游戏周及稳定结算身份绑定，应用组不另建额度。无挑战且没有待领取任务时，零次计划可以直接跳过；有待领取任务则进入只到入口枢纽的分支，不选副本或再次出战。

持久化接入采用“当前周已提交结算减去已完成领取检查所绑定的结算集合”派生待领取状态，避免先写计数、后写另一个领取开关之间的崩溃窗口。领取检查开始前冻结这批结算身份，只能清除本批，不能顺便清除后来提交的另一场。领取完成记录独立去重并保存普通大世界返回证明；未知投递或缺少最终返回不清除待领取。旧周记录保留原周，不移作新周的领取资格；记录损坏或时钟回退须报告错误。

只到枢纽的内部入口分支已实现：`LostVoidEntryFlow::for_bounty` / `LostVoidEntryRun::for_bounty` 接受常规或周期入口，两张同页新帧后交回 `HubReady`，不会选择副本或切换副本页签；已有副本详情则返回枢纽，即便它正好是配置中的目标。未知帧、页签改变及暂停撤销旧到达票数；该回执不提供出战、领取完成或挑战成功证明。原常规入口图在矩阵配置下完成零输入交接，六项新增用例及二十九项入口 / 记录共享测试通过。另补未来周汇总丢失后的时钟回退检查，已提交证据仍可阻止采用错误进度。严格检查和原生构建通过，证据为 `artifacts/lost-void-hub-verification.json`。

只领取分支仍须从新帧确认常规 / 周期入口，随后交给独立领取执行器；不能用手工序列化的检查点生成“已经领取”的证明。只有领取检查执行器安全确认普通大世界，才能清除本次绑定的待领取身份并结束应用。记录恢复仅重放文件提交；领取输入的继续资格由本进程实际执行器保留，跨进程重启只按新帧重新进入检查流程，未知投递不自动重放。入口、领取记录与待领取派生已接入内部应用循环，正式运行入口仍待接入。

应用层的活动预算贯穿全部挑战、记账和领奖，不因新挑战、暂停或重开而增加。实际失败 / 超时退出即便安全返回入口，也应在必要领奖后交回失败，不能另开一场绕过三次重开额度；只有明确通关后才重新计算目标并开始下一场。每场有独立挑战 UUID，账号、应用组配置及候选脚本在应用首次输入前冻结；后续只从原编译结果派生新挑战，跨周重新计算 UP 使用状态时仍须覆盖可能的选队分支。已满悬赏的入口读数须通过独立领取检查记录保存，不能伪造一场结算来更新进度；跨周读数也不能归到新周。

内部 `LostVoidApplicationRun` 已接通并通过现有离线回放。它在同一记录锁内先补交待提交证据，再一致读取进度和待领取批次；只读预览不调用该执行接口，仍不创建文件。初次运行优先处理旧待领取，当前运行明确通关后可继续下一场并在目标达到时统一领取。日 / 周目标已满但有待领取时不能跳过，零目标且无待领取才可零输入交回。`FrozenLostVoidPreparation::for_next_challenge` 只派生新 UUID 和当前周 UP 使用状态，任何新增脚本或代理人分支必须已在应用首次输入前编译与冻结。

### 正式运行入口接入约束

独立运行和应用组复用已有运行槽、账号确认、输入确认及工作线程。迷失之地须在整组第一次输入前冻结配置、队伍、脚本修订和所有可能的候选脚本及资源；即使邮件或咖啡排在前面，也不能延迟到迷失之地分项才读取这些依赖。后续资源核对失败必须阻止输入。日周目标按账号重新读取专用记录，不能仅因本游戏日存在一次应用成功记录就跳过剩余周目标或待领取。

用于运行历史的摘要和待补交记录类型在 `od-core::lost_void_application` 定义，并已挂接 `RunRecord`、运行槽和历史存储；核心层不反向依赖引擎执行器快照。摘要保留冻结账号、配置修订、阶段、活动时间、挑战与领取数量、结束性质及输入释放状态；待补交结算和领取证据只用于幂等写回。实际应用与子执行器留在原工作线程内，暂停继续沿用这些对象，不从历史 JSON 重建输入资格。进程退出后的输入恢复与记录补交分别处理，未知投递不得自动重放。

现有 v10 混合战斗输入恢复已覆盖固定界面键、WASD 及冻结战斗绑定，迷失之地可复用其输入集合和验证规则，不修改旧版本含义；桌面命令选择仍需登记迷失之地并冻结同一份战斗设置。运行槽的输入释放聚合、账号配置操作守卫和桌面状态必须同时检查迷失之地摘要，不能仅在工作线程中处理释放。

分项成功须同时满足实际应用安全交回、`ApplicationOutcome::successful()`、记录提交完成及输入释放；挑战失败后安全领取返回仍应终止该分项。前端进度、运行历史、停止 / 暂停和输入恢复登记都需要覆盖该摘要；完整回放通过前，默认资源与正式可用标记保持现有状态。这些入口接入仍待实现。

### 运行摘要与只补交记录

内部 `LostVoidAppProgress` 保存应用状态、实际结束类型、完成性质、冻结账号 / 区服 / 组 / 配置修订、活动预算、次数、当前挑战 UUID 及已提交记录 ID。待补交结算、领取保留严格类型及原完成日；它们可以反序列化后交给 `replay_pending` 幂等写回，不能据此创建或继续游戏执行器，也不会把原摘要变成运行成功。相同领取 ID 在暂停后的实际返回复验中可以再次出现，但内容冲突仍拒绝。

`verify_committed` 只读核对原始结算和领取文件，复验账号、区服、应用身份、挑战去重、明确通关次数和失败性质；安全结束时，本次提交的结算必须已由本次领取批次绑定。缺失、损坏或被其他应用的领取替代均报告错误，不补造文件。后来的其他运行可以增加账号进度，不会改变原摘要引用的事实。

`LostVoidApplicationRun::with_run_context` 只能在首次执行前冻结摘要身份。`execute_with_progress` 的中间保存回调只提供尚未完成的摘要，实际终态由执行返回后的 `progress()` 从仍有效的实际回执提取；快照中残留的完成候选不会进入成功摘要。`Ready` 中的挑战失败仍映射失败。迟到父暂停 / 停止通过 `acknowledge_parent_interrupt` 接纳，暂停继续沿用原对象并重新确认返回，停止不得继续或重绑身份。

### 运行槽、历史与桌面摘要

`RunSlot` 只接受冻结身份的首次空摘要，不从历史恢复执行器。应用组在启动时冻结迷失之地配置，即使前项仍在执行，后续也不能换用另一套方案。进度只能增加活动时间、次数及已提交 ID，待补交事实不能被替换或无凭据清除。通用 `finish` 不能声明迷失之地成功；专用完成核验区分目标已满的跳过、通关后返回和安全返回后的挑战失败。父暂停 / 停止优先于迟到的 Ready，后续其他分项的控制不修改已结束的迷失之地摘要。

协议 v53 和生成的 TypeScript 包含可选摘要及组配置。桌面当前任务和历史显示阶段、核实通关次数、日周进度、待补交结算 / 领取及输入释放，准备次数不作为通关次数；专用超时参与历史筛选。迷失之地不进入通用“当天成功即跳过”索引，之后每次仍须核对日周目标及待领取。该阶段尚未开放工作线程分派，后续接入见下节。

只在完整“预备编队 / 出战”页面读取固定计数区域，完整且唯一的三字形计数才作为观察。原图 SDK 检查实际读到 `313`，支持参考选队器已有的斜线识为 `1` 别名；单个数字、缺字、重复或冲突不补值。已选择的预备编队可沿用本次槽位人数，但页面明确冲突时停止。保持当前必须得到明确非零计数，连续两张新帧相同后才提供出战意图；动作投递前再次读取相同人数，变化或缺失撤销输入资格。明确未投递后重新确认，未知投递或暂停保留原人数及出战意图，不重复出战。

出战回执保存已冻结人数，到达局内后才交给 HUD 完整名单核对；不把部分头像当人数来源，也不默认三人。矩阵继续依赖完整主战 / 协战证明。少人出战确认与入口更新弹窗继续属于后续开发，计数实现本身不证明这些分支已完成。

本阶段 13 项核心出战用例通过，新增五项；SDK 原 17 项回放中 16 项通过，一项原图 OCR 检查暴露 `313` 别名。按原图和参考选队器补齐完整三字形别名后，全部七项出战 SDK 用例重跑通过，保留原失败日志；合计 30 个不同 Rust 用例，新增七项。原图只读 OCR、原始单 / 双人计数像素与中文出战按钮的标注组合帧、无 HUD 的初始武备后态，以及完整准备中的实际人数传递分别验证，不声称当前中文单 / 双人迷失之地实机通过。工作区及专项严格 Clippy、原生构建、格式、差异和新资源纯检查的证据见 `artifacts/lost-void-deploy-count-verification.json`。场景仍为 schema 1、254 份参考来源、107 个文件，本地来源增至三份；release 包等剩余确认 / 更新代码完成后统一重建。

### 少人出战确认

普通本次出战已冻结为一人或两人时，可以处理明确缺员且询问继续出战的弹窗。正文必须共同说明队伍 / 代理人、人数 / 数量 / 空位不足以及继续目的；同义表述可包括“不满三人”“数量较少”，支付、养成、物品、返回 / 退出和不能继续等不同用途不提供许可。`common_deploy.yml` 只提供“确认”按钮区域，没有正文原图；当前样例均标注为语义组合，不冒充实机原文。

适配器要求固定按钮区与弹窗区都读到唯一完整“确认”，并指向同一位置；单独确认或背景出战按钮不能授权。核心状态机另有少人确认意图与两次新帧计数，三人、未知人数和本次出战前已有弹窗不点击。保存意图后，实际投递前再次核对新帧正文及按钮；确认最多一次，明确未投递后才可重试，未知投递或暂停保留原意图。少人和低等级提示可分别处理，互不覆盖投递记录。

SDK 仅使用原始人数像素、明确标注的中文语义组合弹窗及原始初始武备后态，验证单人 / 双人确认、可选后继低等级、正文变化、保存失败、迟到停止及暂停继续。不能继续或不同用途的确认不产生点击。没有实际游戏确认正文留档，全部实机与性能验收保留；入口更新弹窗与最终匹配发布包继续开发。

本阶段 18 项核心及 11 项出战 SDK 用例通过，共 29 个不同用例，新增九项。完整 SDK 目标通过后，分别补跑同义正文正向用例及否定正文、既有弹窗、三人和未知用途的负向用例，覆盖原图一 / 双人计数和后继低等级提示；重复用例不重复计数。工作区 / 专项严格 Clippy、原生构建、格式、两仓差异及配套资源纯检查通过，实际回执、范围和源码 / 引擎指纹见 `artifacts/lost-void-short-party-verification.json`。没有前端或协议字段变化，输入恢复保持 v10。

### 异常恢复设计

来源 `lost_void_run_level.py::handle_find_target_fail` 将寻路超时、战斗超时和实际阵亡计入同一层的三次重开额度。重开次数在发起重开时占用，投递未知或暂停不能重新分配新身份再消耗一次。每次保留同一层的根身份与新的尝试身份；正常跨层建立新额度，重开成功重建尝试内的 NPC、武备重复、移动和卡住状态，总挑战活动预算不随重开增长。

入口已完成至少一次首槽武备选择且尚未放弃感叹号时，寻路超时先沿用当前尝试直接找出口，不消耗重开额度，也不撤销已完成武备。该分支只处理寻路失败，不能让阵亡绕开恢复。新寻路执行器重建画面与镜头证明；若出口仍超时，继续共享的重开策略。重开失败不当作新层到达；额度耗尽则发起有来源的退出，并保持失败性质直到结算返回。

恢复核心只管理失败身份、预留重开意图、已确认尝试及三次上限，不提供输入或到达证明。实际执行器仍须消费同控制的真实层失败，保存打开菜单 / 重开或退出 / 确认的独立意图，并从新帧确认返回后态，才能建立下一次层执行。参考 `RestartInBattle` 与 `ExitInBattle` 只有按钮确认，Rust 适配必须核对本次操作上下文，不能确认任意已有弹窗；相关菜单与确认态暂无留档原图，组合回放须明确标注，正式验收保留。

`LayerRetryBudget` 提供额度与身份的独立核心，`RecoveryFlow` 提供菜单意图及后态协议；核心阶段 21 项专项及 26 项相关回归通过。重复失败保留原重开意图，确认过的旧失败返回已处理；检查点后继不能清除失败历史、撤销已确认状态或更换层身份。入口找出口需要实际完成首槽武备及移动后可导航的记忆，战斗超时与阵亡不使用此分支。菜单输入、实际重开到达及挑战父流程已由下方执行器接入，实机验收仍保留。

恢复菜单状态机分别保存打开菜单、重开 / 退出和确认。只有同次命令的明确用途确认才能继续，未知确认不点击；暂停撤销按钮及返回新帧计数，保留已发生的命令和明确加载历史。重开确认之后须观察明确加载，再核对两张完整同队伍世界新帧或已知初始局内选择页，才提供预留尝试身份的实际到达回执；没有加载时，仅返回原世界不清空本层记忆。退出或恢复途中自然出现的结果页直接交给结算，并保留失败来源，恢复状态机本身不点击完成、不记通关。

接入父流程时还须区分子步骤超时与总预算耗尽，后者不能重置计时再发起恢复。导航已经提交或未知投递的门交互需要先处理原交接来源；不能仅凭等待超时，就把可能已发生的跨层当作旧层寻路失败重新开始。真实重开回执消费后才确认额度中的新尝试，恢复核心的序列化意图本身不能构造生产层执行器。

内部恢复执行器已接通并通过离线执行回归。`LostVoidRecoveryRun::after_level` 只接收同控制的实际失败层执行器，并一次性预留交接；配置或反序列化的重开意图不能直接构造它。单次挑战增加恢复阶段，只有尚有总预算的导航 / 战斗自身超时，或实际战斗阵亡，才进入恢复。层内保留超时来源，避免父预算限制的慢识别被误算成步骤超时；迟到暂停后仍可交回同一失败，不重新执行已经超时的子步骤。

重开到达回执只能消费一次：确认预算中的新尝试后，重建 NPC、导航、武备重复和卡住状态，并恢复尝试开始时的选择规则；入口直接找门则保留已完成武备、当前规则和尝试身份。正常换层重建三次额度，重开不增加层数或单次挑战总预算。恢复途中结果交接结算时携带 `Aborted` 层结果和实际失败身份；导航 / 战斗超时退出保留 `CompletionKind::Aborted`，阵亡退出为 `Defeated`，两者均不产生通关或周上限证明。

原生菜单观察沿用 `battle_menu.yml` 的返回、战况、设置、重新开始、退出战斗及确认区域。菜单页须有返回和两个页签的共同上下文，命令与确认还须为可用白字；确认正文必须明确询问重开或退出本次挑战 / 战斗，并与本次命令一致。未知、混合用途、取消或支付正文不产生确认许可。当前缺少这些菜单与确认原图，先以固定定义和标注组合帧验证；不能将组合正文当作游戏实测文案。
