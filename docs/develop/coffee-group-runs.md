# M3 咖啡应用组、每日记录与邮件交接

当前“账号与应用组”可试运行邮件与咖啡，按保存顺序执行，也可只启用其中一项。咖啡使用所选账号和组的固定参数，从大世界自动开图、传送到澄辉坪汀曼咖啡、交互、点单、确认电量及返回大世界。完整咖啡领取仍待实机验收，应用登记的正式可用标记保持待验收。

## 运行与交接

启动只提交账号、组、修订、预览游戏日及输入确认，不接受客户端提供的执行列表或参数。引擎重读配置和完成记录，复验当前账号、配置修订、游戏日及预检期间是否发生另一运行；冻结邮件参数和咖啡参数。其他启用的未知或未迁移应用继续阻止整组启动，不自动切换游戏登录。

整组只占用一个运行槽和运行 ID。首个账号记录完整写盘后才进入工作线程，所有待执行项的固定资源在任何游戏输入前检查；缺少咖啡 v2 或地图包时，邮件也不先执行。已有协议 v22 的自动路线完整包可以继续使用，不自动从另一个版本补文件。

每项开始前保存分项检查点；完成后确认执行器输入释放、保存分项结果，再启动下一项。鼠标、键盘、控制器和 Maa Tasker 的使用保持顺序，切换执行器先结束旧工作并释放输入。邮件与咖啡可以互换顺序；每个应用使用自己的有效超时及启动 / 继续延时。

暂停保留当前执行器和业务检查点，同 ID 继续；在两项之间暂停时尚未创建后继输入工作。交接结果保存失败会停在这个边界，继续按钮不可用；修复目录并“重试保存运行记录”只保存记录，之后需手动继续。后继启动检查点保存失败时，不发送后继输入并结束组。停止、失败、超时或未确认输入释放均不启动后继；未释放输入的组也阻止新任务。终态保存失败继续沿用现有重试和恢复拦截。

## 账号历史和每日完成

记录继续保存到 `runs/accounts/<四位编号>/<运行ID>.json`，保留账号、组名、配置修订、游戏日、分项顺序与起止时间、每项输入释放及邮件 / 咖啡业务进度。只有邮件的组保持原 `email` 标识；包含咖啡的组使用 `application_group`，仍是一个账号记录。独立诊断不写入账号每日成功。

每日完成按应用逐项判断。成功分项必须已完整保存，时间属于该区服的同一个游戏日，开始不早于组开始，结束不晚于查询或已知组结束；分项与冻结计划一致。邮件须完成并确认输入释放；咖啡还须有本次点单、电量出现、前置完成和最终返回大世界的证明。仅传送、进入对话、已喝过、已有奖励、失败或跳过都不能生成咖啡成功。

后项失败或引擎在后项中断，不抹去前项已经保存的成功证明；下一次按日计划可以跳过它。暂停和继续只改当前分项，不改已完成应用的成功状态。按日跳过只引用旧记录，不在新组中制造新的成功分项；跨每日重置的分项不作为当日完成。坏文件计数并提示，不能读取完成目录时拒绝启动。

## 桌面输入恢复

桌面在发送应用组启动前登记 v6 恢复计划，固定只允许释放 Alt、鼠标左键、N 和 F；不根据前端提交的动作扩展范围。继续前核对同一运行及磁盘登记。只有同 ID、组终态、账号计划一致，且全部分项与业务进度均确认释放，才能清除登记；停止应答或邮件先完成不能提前清除。

协议升级为 v24，桌面、引擎与生成类型需配套更新。资源内容不变，继续兼容 schema 1 / 协议 15..23 和 schema 2 / 协议 16..23。旧诊断的 v1..5 输入恢复记录仍可读取；v6 不是任意输入或动作重放接口。

## 试用

1. 重启配套桌面与引擎，确认当前资源含咖啡 v2、地图及邮件。
2. 连接 1080p 游戏，确认当前账号当天仍可喝咖啡，停在大世界。
3. 在“账号与应用组”只启用邮件和咖啡，先按邮件 → 咖啡排列；保存所需咖啡、超时和延时。
4. 预览账号、顺序、两项实际参数及每日策略，确认前台输入后启动，在延时内切回游戏。
5. 检查邮件返回大世界后再自动开图和点单；确认咖啡电量及返回大世界，核对两个分项、输入释放及账号历史。只有这些成立，才可将按日策略下的再次预览作为咖啡每日成功的实机验收。

## 验证范围

新增 6 项核心回归覆盖双向顺序、保存屏障、同 ID、暂停与停止交接、部分成功后的每日跳过、咖啡完整证明、时间边界及输入未释放时阻止新任务。核心成功用例构造业务证明，只验证调度和持久化规则。

新增 2 项真实 SDK 模拟控制器回归使用已有邮件、地图、大世界及旧咖啡留档，验证邮件 → 咖啡点单后暂停、继续 / 停止不重复动作，以及交接结果写盘失败、重试保存后手动继续；损坏咖啡资源时整个组在邮件输入前失败。这些画面仍不含缺失的电量和增益原图，不能证明完整领取或真实游戏通过。

另新增 1 项 v6 恢复范围及全分项释放证明回归，更新真实命名管道模拟引擎的组登记、暂停继续和收尾；新增 3 项界面用例覆盖参数预览、当前分项的输入状态、同 ID 控制、分别跳过、保存撤销预览和结果未保存时禁止继续。

本机输入恢复 33 项中 31 项通过。两个既有 Win32 前台保护用例在沙箱与普通权限下均被 GDI 截图尺寸检查提前拒绝，未走到预期的前台校验，保留未通过；不放宽断言或将其计为游戏验收。真实游戏的完整咖啡、每日记录、双向交接及边界仍待实机验收。详细结果见[验收记录](../migration/acceptance.md)。
