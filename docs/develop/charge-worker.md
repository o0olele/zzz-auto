# 体力父流程与页面交接

## 区域巡防父循环

普通区域巡防、专业挑战、深度追猎及这三类代理人挑战已接入父循环。带战斗的构造入口从同一 ConfigStore 读取并冻结当前账号战斗设置、脚本目录修订及各启用战斗计划的已编译脚本，首个导航输入前预检对应资源。原不带战斗的构造入口不能接收这些战斗计划；模拟室代理人计划因缺少生产选中证明，仍在整组预检时拒绝。指定等级现支持普通深度追猎，其余分类仍要求默认等级。暂停不重新读入脚本或切换窗口。

父流程拥有唯一 Option<NativeSession> 槽位，交给区域子任务后不创建并行控制器。区域执行负责界面与战斗设备交接；回交后父流程恢复冻结窗口、截图方式和前台 CPU 界面会话，重新加载导航依赖。区域详情只在独立 60 电量识别与实际返回模板共同出现时允许返回；已发送或不确定的返回意图跨暂停保留。弹窗和战斗页面不使用兜底返回。

区域正常完成或实际不足先进入只登记阶段。已取得的正常结果先写日志和次数，再处理迟到的暂停、停止、跨日或配置变化；保存失败仅补交，不再挑战。之后返回大世界、打开手册、同帧重读资源，依原计划顺序选择下一项。每轮创建新的挑战执行 UUID，旧成功不能用于循环中的下一次计数。父任务总预算包含子任务、检查点与结果保存耗时。

`ChargeWorker` 将实际资源读取、计划选择、电池合成、区域巡防、专业挑战、深度追猎、三类代理人挑战、次数保存及下一轮交接接到同一个内部父流程。当前未登记为桌面或应用组可执行应用，协议 v47、导入预览 v19 和正式可用标记保持不变。模拟室可以进入已有传送和选关准备，但选中态回执仍固定未验证，不能进入消费或登记次数。模拟室代理人选择投递已有独立子流程，整组消费预检仍说明其缺少的执行能力。

区域巡防、专业挑战与恶名狩猎现已增加独立的[传送子流程](charge-transport.md)，到达本身不提供消费许可。[区域巡防单次挑战](area-patrol.md)、[专业挑战室](expert-challenge.md)和[深度追猎](deep-hunt.md)通过 `new_with_combat` 接入父循环，采用独立电量与恢复、选队、出战、战斗、结算和登记；原 `new` 缺少冻结战斗上下文时继续拒绝这三类计划。

专业挑战只接普通默认等级，消费前须明确读到燃竭 OFF 及实际需要 40 电量。关闭燃竭与确认分别保存意图，未命中 ON 不能推断 OFF；连续三次已识别详情仍缺少明确模式或正确费用时，父流程返回 `AwaitingVerification`，不点击下一步或登记成功。专业详情、OFF 与关闭确认缺少真实留档，目前仅合成画面回放通过，实际文案与操作保留实机验收。专业结果保存后可接区域或合成，返回导航须同时具备专业详情与实际返回模板。

深度追猎先核对本次完整目标及周常奖励状态。仍有 1..3 次奖励时，无论电量不足跳过设置如何，均登记独立阻挡并在本次运行跳过该项；不增加次数，整组结束保留 `WeeklyRewardsAvailable`。明确耗尽、深度 ON 和实际需要 60 电量才可消费，恢复后重新核对；开启及语义确认保存独立意图。出战后执行距离、交互、鸣徽及搜索移动，移动累计 120 秒活动预算跨暂停保留，随后切换冻结战斗方式。列表、详情及模式确认缺少真实留档，当前为合成画面回放，实际操作保留验收。

父流程直接持有唯一 `Option<NativeSession>` 槽位，暂停期间外层不能替换其窗口、截图方式或控制器。`ChargeRunSeed` 先冻结账号、应用组、配置修订、游戏日、计划和编队，实际读帧后才绑定双倍余量；未知值不能临时填零。每个输入阶段和检查点保存前后复验当前配置与游戏日，各战斗分支额外复验冻结战斗设置，登记器识别自身计数提交产生的修订。实例不能从序列化快照恢复输入，也不能在终态后直接重跑。

运行顺序为：确认大世界、打开快捷手册、同帧读取三项资源、保存本轮尝试、执行子流程、登记已核实结果、返回大世界，再读取下一轮资源。首次检查双倍时先进入训练中的实战模拟室分类；按[实际余量](charge-double.md)核对完整标签、独立单行次数及分类蓝底，未取得可靠 0..5 次余量时返回 `AwaitingVerification`。电量不足、合成素材不足、计划完成和没有启用计划各有独立终态；空计划不伪造资源读数或成功记录。[应用历史与每日证明](charge-application.md)已接入内部记录适配器，正式独立及应用组执行入口仍待接通。

`ChargeNavFlow` 只处理已识别的大世界、快捷手册、合成页、电池详情、模拟室类型 / 挑战详情及加载独立资源后的区域、专业详情和恶名狩猎列表 / 详情。返回必须命中当前页面的模板，退出手册须先复验完整手册上下文；打开手册复用 Alt 显示图标及重新截图。未知弹窗、消费确认、奖励、出战或战斗页面不能使用通用确认或兜底返回。电池详情只在内存保留完整名称和获取合成入口的候选区域，关闭前重新截图局部核对；候选坐标不写检查点。新帧仍限 1500ms，慢速全屏详情发现只能提供候选，不能直接授权旧帧点击。

每个导航动作先保存意图；已发送或发送情况不确定时等待页面变化，同一种页面的按钮暂时消失不能触发重复返回。训练和分类切换需要各自真实后态。导航上限为 32 次动作，活动预算和意图跨暂停保留；暂停后撤销旧到达回执。页面到达不证明消费或任务成功。

结果登记采用已有[体力次数持久化](charge-history.md)。本次合成、区域、专业或追猎挑战须先取得父、子均正常保存和释放输入的结果；之后出现的暂停、停止、超时或配置变化不能撤销已经取得的消费日志。配置提交冲突或失败时返回 `AwaitingSave`，禁止再次执行；`retry_saved_result` 仅补交原结果，即使停止后也不发送输入。冲突配置保留原文，日志保留证据。计数保存后才交接下一轮，资源和配置重新读取。

导航资源独立为 schema 1，锁定六份参考来源中的返回逻辑和区域定义、固定 OCR、已有转换后的返回 / 关闭模板和只读 Pipeline。原有执行包继续独立校验。开发命令：

只读命令保持 `accepted=false`、`input_sent=false`、`navigation_verified=false`、`completion_verified=false`。回归使用真实留档、明确标注的详情和资源变化组合图以及真实 Maa SDK 的自定义控制器；组合回放不能替代实机验收。用户选择暂不启动游戏，本轮没有启动或连接真实游戏。实际长时间循环、设备交接、暂停停止及异常恢复、完整关卡选中态、双倍活动与无活动证明及剩余副本继续保留。
