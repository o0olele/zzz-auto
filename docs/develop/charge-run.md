# 体力计划循环与挑战次数登记核心

`od_core::charge_run::ChargeSchedule` 冻结运行 ID、账号、应用组、配置修订、区服游戏日、完整体力设置及编队。它生成逐次尝试并重放登记日志；`zzz_engine::charge_run::ChargeRegistrar` 连接实际 `SimulationChallengeRun`、`SynthesisRun`、`AreaPatrolRun`、`ExpertChallengeRun`、`DeepHuntRun` 的终态和外层检查点保存回调。已接通[次数保存与启动恢复](charge-history.md)、[快捷手册资源读取](charge-resources.md)及[目录兼容](charge-catalog-compatibility.md)。完整体力应用工作线程和桌面运行入口继续开发。

规则沿用参考仓[体力计划玩法](../../../ZenlessZoneZero-OneDragon/docs/develop/zzz/application/charge_plan.md)与已有[体力配置估算](remaining-game-apps.md#体力计划配置与估算)：一次完整挑战增加一次计划次数，卡片数量只影响实际电量；零目标停用，每日重置按区服与游戏日，整轮扣减保留超额。旧次数只作为冻结基线，不能变成本次成功证明。来源更新单独审核，旧资源按冻结版本继续校验，详见目录兼容说明。

每次选择采用调用方提供的当前资源读数，依保存顺序比较电量和允许的恢复来源；两个单独不足的来源不相加。估算只决定是否值得进入，实际准备返回电量不足时不计成功，按冻结开关结束或在本次运行跳过该计划。已跳过项不在后续电量变化时自动重试；跳过不能被视为整轮完成。当前接受模拟室、[单次电池合成](ether-synthesis.md)、[区域巡防单次挑战](area-patrol.md)、[专业挑战室](expert-challenge.md)和[深度追猎](deep-hunt.md)各自的回执，不允许跨分类采用。区域结果只接受实际需求 60 电量，专业只接受燃竭明确关闭后的 40 电量，追猎须周常耗尽、深度 ON 和实际 60 电量，均不能用于模拟室双倍临时计划。周常尚有奖励单独登记阻挡，跳过当前项且不计成功，整组保留 WeeklyRewardsAvailable。

开启双倍须先提供明确的 0..5 次余量。首次选择最多按当前电量生成一次临时卡片计划，优先于正式列表；成功或不足后均不重复生成。临时计划即使与正式项 ID 相同也不增加正式次数；临时不足同样遵守跳过设置，不产生完整成功。零余量和当前电量不足以支付一张时不生成临时挑战。

每次尝试包含运行 ID、递增序号、完整计划、解析后的脚本及用于估算的资源读数。首次输入之前，外层须成功保存带有 `pending` 的整个检查点；保存失败不返回输入许可。保存期间收到暂停时保留已保存意图，继续后可重新取出，实际挑战仍重新读取关卡和电量。任何账号、组、修订、运行或游戏日变化，以及待处理暂停 / 停止，都阻止交接。

登记只从实际挑战实例取得成功或电量不足终态，同时核对同一控制句柄、运行、冻结计划、编队和恢复设置；未完成、失败、停止、超时、保存失败、未释放输入或待处理控制请求不能提供成功证明。挑战实例持有独立 `execution_id`，暂停继续保持同一个值。登记日志拒绝重复采用该执行结果，因此即使循环扣减后计划内容完全相同，也不能将上轮结果再次计数。

结果保存回调成功后才提交内存次数；失败时保持原待登记尝试，重试同一结果，不重新挑战。同一回执重复提交不增加次数或再次写入；不同结果不能覆盖旧记录。已取得正常终态后，若保存期间收到控制请求，保留已经确认的次数并阻止后继。外层负责将保存耗时纳入自身总活动预算，登记器不重新计算或延长游戏执行预算。

检查点 schema 1 包含冻结请求、有界日志、当前意图及可选结束证明。反序列化后须调用 `validate()`，按原顺序重放每日重置、循环、跳过、临时计划和结果，拒绝序号、计划、脚本、卡片、重复执行 ID 或结束证明不一致；每个运行最多 4096 次尝试。`progress()` 给出本次次数投影，原请求不改写；持久化接口只提交已经确认的日志前缀。日志不构成游戏输入的恢复入口。

```powershell
cargo test --locked --manifest-path zzz-od-test/test/zzz_auto/rust/Cargo.toml --target-dir target/validation-restore-charge --test charge_run -- --test-threads=1
cargo test --locked --manifest-path zzz-od-test/test/zzz_auto/rust/Cargo.toml --target-dir target/validation-restore-charge --test simulation_challenge -- --test-threads=1
```

回放采用真实 Maa SDK、自定义控制器和通过生产校验器的固定执行包。已验证关卡是明确构造的测试前置；生产选关回执仍固定未验证。关卡选中素材与生产者、实际双倍与无活动证明、传送到挑战的完整自动循环、应用运行历史、剩余副本及全部实机验收继续保留。当前协议 v47、导入预览 v19，正式可用标记不变；资源版本沿用各自冻结校验。

后续已接入[内部体力父流程](charge-worker.md)：大世界起点与返回、实时资源、电池合成计数及下一轮交接使用同一原生会话。`ChargeRunSeed` 将配置冻结与实际双倍绑定分开；实际双倍未知时不能构造执行请求。模拟室传送和选关沿用未验证边界，其他消费执行器、正式应用运行历史与每日登记仍待接入。
