## 三项领取流程

来源为参考仓三个 Application、对应 screen_info 和画面文档；留档包含丽都周纪 BINGO 主画面、卦象主界面及共享次数提示。饼铺、卦象滑动和新领奖后态仍缺真实截图，按旧流程实现后由模拟控制器验证分支，实机继续待验收。

丽都周纪从快捷手册日常页进入，先以积分特赏、三格连线额外奖励共同确认 BINGO 页面，再按原白色过滤识别三行的 100 积分。灰色未完成任务不能作为可领取积分。领取后重新检查，点击奖励后要求重新回到已识别页面且无可领取积分；奖励弹窗只在本次领取操作后处理。不能将未知画面或超时当成无奖励。

卦象集录从澄辉坪 → 阿朔进入，饼铺从布亚斯特城区 → 吼吼饼铺进入。沿用已解锁、地图文字可见的固定路线；确认传送后暂停不会重新传送。到位等待后按 F 交互，无额外前移。

共享次数提示优先于普通确认。卦象需要识别滑动提示才拖动，并在本次领取上下文中处理确认；确认后返回主界面或大世界才完成。饼铺依次检查集卡机、居中盲盒和确认，最后以“今日已领取同类型奖励”或共享次数弹窗完成。任意“确认”或普通大世界画面不能单独构成领奖证明。

三项领取流程从 schema 2 起提供；当前新日常资源为 schema 6，保留 schema 1 的三项、schema 2 的六项、schema 3 的七项、schema 4 的八项及 schema 5 的九项固定定义。整组资源预检按实际应用核对包版本，避免先执行邮件才发现后项缺资源。旧输入恢复 v7 已覆盖这些流程所用的 Alt、Escape、N、F 和左键。

## 驱动盘拆解

“账号与应用组”按组保存 B / A及以下 / S及以下及“全选已弃置”。等级用于未弃置驱动盘，弃置选项与等级选择分别操作；默认 A及以下、不全选已弃置。预览显示冻结规则及消耗说明，运行确认包含按此规则拆解；执行中不能更改设置。复制、备份恢复、离线恢复和旧配置预览均保留并展示设置。旧组内 `drive_disc_dismantle.yml` 优先于旧账号级文件，无效等级或布尔值阻止导入；导入预览版本 v11。

流程从大世界进入菜单、仓库；若处于音擎仓库则切换驱动仓库。进入拆解页后依次快速选择、重置、选等级、可选的全选已弃置、应用筛选。每步要求对应画面和操作完成，筛选失败即停止。应用筛选之后明确识别 `0/300` 才走空选择分支；非零数量进入拆解确认。确认弹窗要求拆解语义及取消、确认按钮共同出现；提交后只有获得弹窗能证明拆解结果。两条分支均要求先返回驱动仓库再返回大世界，并确认输入释放后才保存成功。

确认前暂停会清除筛选证明；继续时若仍停在确认弹窗，先取消并重新重置、选择。确认已经投递则只等待获得后态，不自动再次确认，也不把返回零项视作成功。确认前停止不提交拆解。当前与后继分项沿用同一运行 ID 和冻结设置，检查点更新拒绝删除或修改拆解参数。

模态可能透出底页文字。输入之前通过优先识别确认、筛选和获得弹窗拦截不适用的页面动作，不能依赖复合识别的内联 `inverse`。驱动盘拆解要求 schema 3 日常包，来源锁定四份 screen_info；未增加模板或输入种类。

默认、筛选、驱动仓库、菜单和大世界用真实留档做离线推进；获得弹窗复用道具处理留档。测试中的非零选择和拆解确认帧为黑底文字合成图，位于独立测试仓库 `test/zzz_auto/fixtures/dismantle-*.png`，只验证分支，不是游戏素材。筛选选中颜色、拆解确认及真实材料奖励、音擎仓库切换仍需实机验收。

## 兑换码

“通用设置”保存所有账号共用的用户码表和有效期，最多合并 256 个码。同名用户码覆盖随附码表；有效期包含截止当天，设为过去日期可以停用内置码。计划按游戏日、旧版已处理列表和新运行的逐码历史筛选；没有待处理有效码时显示明确的跳过原因，不打开游戏输入。当天新增有效码仍可运行，不受整个应用的每日成功标记阻挡。

旧根目录 `redemption_codes.sample.yml` 和 `redemption_codes.yml` 按示例、用户顺序合并转换；`01/app_run_record/redemption_code.yml` 的 `used_code_list` 按账号保留。旧版再次点击按钮即登记已用，导入记录仅代表旧版已处理，不转换为成功结果。复制账号不复制这份旧处理记录，新运行结果由账号运行历史隔离。导入预览版本 v12，备份、离线恢复和导入界面展示码表及旧记录。

冻结码表后，从大世界 → 菜单 → 更多功能 → 兑换码页，依次聚焦输入、Ctrl+A、退格、输入冻结文本、OCR 核对完整文本后提交。每个码区分兑换成功、已兑换、无效、过期；未知提示或单次按钮动作不构成结果。确定结果跨游戏日保存，后续码失败、停止或超时不撤销之前的结果。配置和检查点更新拒绝改变冻结码表、撤销或改写已有结果；损坏结果不用于跳过并计入不可读告警。

提交前暂停使输入核对失效，继续时重新清空并输入；已经尝试提交则只等待后态，不能自动再点兑换。进入流程前的旧结果只关闭，不归入当前码。所有码处理完且返回大世界、输入释放后才完成应用。整批共用日常超时；部分完成后下一次只处理未取得结果的码。

兑换码需要 schema 4 日常包；来源锁定菜单、更多功能 screen_info 和示例码表，新增 Ctrl、A、退格的 v9 固定输入恢复清单，旧 v7 与战斗 v8 保持原义。协议 v37。码表来自随附参考文件，不代表已在线验证可用。菜单、更多功能、空输入页和大世界使用真实留档；输入文本与四类结果使用标注“离线测试”的合成帧，真实文本渲染、服务器提示、实际兑换与奖励到账仍待验收。

## 录像店经营

录像店保留旧版三处营业入口：录像店柜台、澄辉坪营业点、布亚斯特城区营业点。柜台和布亚斯特入口先转向正东再前移；澄辉坪直接交互。入口、两名宣传员和鼠标转向系数按账号与组保存，独立计划、应用组计划和运行检查点冻结这些设置与游戏日。复制、备份、离线恢复和导入预览保留设置。旧组内 `random_play.yml` 优先于账号级文件，转向系数读取账号 `game.yml`；导入预览升级 v13。

到店后处理旁白、查看经营状况和昨日账本。已在营业以明确营业文字确认，再返回大世界完成。未营业则选宣传员：按冻结游戏日的奇偶轮换两名候选；任意名称为“随机”时轮换前两个位置。指定候选先按文字、再按对应头像特征匹配；最多滚动两次，仍未找到则选当前列表首项。已选宣传员保留。来源清单含 60 名代理人、84 个头像模板，连同地图按钮共 85 个模板；原二值掩码转换为 Maa 绿色掩码，构建和加载均检查固定内容。

在同一截图读取三个主题，采用旧版相似度阈值和默认顺序补齐有效且不重复的主题；评分包含识别文本长度，长串噪声不能仅因含有主题字样就通过。先尝试推荐上架，再检查三个录像带标题；没有推荐或未补齐时逐主题打开筛选、选择类型、关闭筛选、选择录像带。每次上架必须看到“下架”状态，三个主题完成后再次核对主界面的录像带标题，才允许开始营业。弹窗优先识别，关闭账本、筛选及营业确认后等待弹窗消失，避免底页透出的文字提前推进。

提交营业前暂停会撤销选择证明；继续时重新识别，若停在未提交的确认框则先取消。提交动作前先保存检查点，提交后只等待“丁尼广进 / 生意兴隆”或“正在营业”，不重复确认，不把普通主界面或大世界视为成功。完成后返回大世界并释放输入，才记录应用成功。传送或前移投递后暂停不重复执行；交互等待失败最多重新传送一次，营业提交后禁止该重试。

录像店需要 schema 5 日常执行包及协议 v38，输入恢复沿用 v9。已接入独立运行、应用组交接、实时进度和历史展示。测试使用真实昨日账本、已营业、宣传员选择、营业确认及结果留档，配合标注用途的合成主题与录像带画面；正式可用标记仍待实机验收。

## 录像店与路径共用转向

`od-core::navigation` 提供绝对角差、鼠标标定和逐次反馈补偿；`maa-adapter::navigation` 复用 Maa 截图、地图按钮模板定位和相对鼠标输入。模板左上角减去 `(169,151)` 得到 210×210 小地图，未定位时按参考版使用勘域静态框。框中心必须有符合旧版 HSV、周长与面积条件的玩家图标；偏移框、无图标和不明确扇形均不产生输入。地图与扇形识别使用同一帧，不缓存上一场景的裁剪框。

朝向识别保留旧版 YUV 掩码、3×3 闭开运算与模糊、极坐标展开、Scharr 梯度、峰值及 105° 扇形匹配。普通 Maa 识别没有这项算法，因此这部分在 Rust 中执行。反馈补偿范围为 0.5..2，每次最多调整 0.1，接近半圈的过冲按同方向展开；单次输入不超过半圈，最多 32 次。默认标定为旧版的 -5.5 像素/度，调用参数接受 -50..=-0.1。是否到位需要两张新截图连续落在 ±2°；超过 500ms 的旧帧、缺失识别会清除连续确认及待学习样本。

调用方须先确认大世界画面并持有运行槽。整段转向最长 30 秒，每次输入前检查取消；截图或输入失败直接返回，不重试不确定输入。暂停后重新识别并校正，不能重放前一次鼠标位移。录像店通过同一 Maa 控制器调用该能力，并在交回 Pipeline 前释放输入；转向系数纳入冻结设置，输入恢复清单保持原义。

独立测试仓中的 `navigation-legacy.json` 记录参考源码、像素 SHA-256 及旧算法实际输出，使用隔离 Python 3.11.9、OpenCV 4.13.0、NumPy 2.4.6、SciPy 1.17.1 采集。23 份小地图文件去重后为 22 张；`172_1.png` 与 `177_1.png` 像素相同。Rust 的角度与保留三位小数的置信度逐项一致，同时满足旧测试的文件名角度 ±10° 预期。Python 仅用于离线对照，正式程序仍全部使用 Rust 与 Maa。模拟控制器验证动态框、静态兜底、缺图、过期帧、反馈补偿、取消、暂停续跑与原生失败；16 项导航及 6 项相邻战斗输入回归通过。这些结果不代表实机转向或录像店验收。
