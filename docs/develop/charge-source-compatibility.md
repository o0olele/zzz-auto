# 体力资源生成与当前参考来源

完整体力目标继续保留模拟室选中证明、无活动证明及实机验收。用户选择暂不启动游戏，本工作只读参考仓和已有画面，不用推测选中态补齐证明。

试运行入口已经接通，但新环境生成共用日常资源时，七份来源不同于主哈希。其中日常页签已有兼容版本，原审计没有计入兼容列表，实际新增不兼容来源为六份。逐份以原锁的 SHA-256 在参考仓本地提交历史中找到旧文件，再与当前工作区比较；对照记录为 artifacts/charge-source-drift-review.json。更新来源必须先迁移实际受影响的数据或行为，不能只替换哈希让检查通过。

当前代理人表只新增菲欧妮及三个头像变体。账号编队校验、宣传员选项和头像识别使用同一份名册，应一起加入新成员及原始模板。日常执行包增加 schema 8；schema 5 至 7 继续使用原六十人名册和八十五份固定图，不要求旧包包含新增模板。使用新包才能识别新增头像；旧包的宣传员完整名称选择保持，头像回退只引用实际包含的模板。体力开始前检查指定编队成员是否在冻结战斗资源中，前序编队扫描更新成员后再次核对；更新日常头像不能替代战斗资源更新。协议升到 v49，新资源包须配套新引擎。

兑换码样例只更换一个带有效期的示例值，实际执行仍使用账号保存的码表。代理人表和样例码表保留原锁并登记经过核对的新来源变体，生成清单记录实际读取的哈希。日常页签区域没有改变，原来已经接受参考文字相似度和黄色范围的变化；本轮只修正审计，Rust 的完整名称及同帧页面判断保持原义。

后续[按槽位扫描](team-slots.md)已迁移管理页的三份变化：按槽位读取、名称同步和头像结果，共用 team_select.yml、predefined_team_recognizer.py 及原始卡片画面。管理页包使用 schema 9、协议 v50，队名去除空白使导入预览升级 v20。[公共战前选择](team-selection-slots.md)随后接入 schema 10、协议 v51，接受当前 ChoosePredefinedTeam 公共路径并单独固定六份来源。当前四十条来源全部匹配，可以直接从当前参考仓生成整套新日常包；schema 1 至 9 仍保留原义。选择期间只记录观察，持久同步由编队检查承担，避免修改冻结的计数修订；式舆自动配队等未迁移应用保持原状态。

复核并删除了上一阶段兼容表中两条文件名与哈希错配的条目：识别器哈希不能用于选择文件，布局哈希不能用于菜单文件。它们此前没有接受当前选择文件，也不改变上次三十九条通过、一条拒绝的实际结果。当前选择来源另行登记实际哈希，并验证全部关联来源；没有放宽为接受任意变化。

新增十项检查覆盖真实转换器的新旧名册分支、来源审计及篡改、三个原始头像的 Maa 特征读取、战斗名册预检和资源包安装；连同体力记录、入口及录像店核心回归，共四十五项通过。新资源转换分支使用明确标注的离线快照，其中四份编队文件来自原锁对应提交，不将其当作当前编队实现的迁移证明。当前参考仓另有拒绝转换用例。详见[验收记录](../migration/acceptance.md#2026-年-10-月-29-日-m5-当前名册与来源兼容核对)。
