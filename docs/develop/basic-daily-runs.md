# M3 首批日常完整执行

M3 首批固定为邮件、咖啡、活跃度奖励、丽都城募和刮刮卡。邮件和咖啡沿用现有执行器，后三项通过 Maa Pipeline 识别、输入和等待，Rust 保存业务检查点。游戏实机验收、缺失状态的真实截图及发布签名按路线图保留待办，不把合成分支测试写成实机通过。

后三项共用账号应用组中的超时和启动 / 继续延时；配置复制、导入、备份和恢复均保留这组参数。运行时冻结保存参数，独立应用入口与应用组使用同一执行器、每日记录、运行槽和输入恢复。

活跃度从大世界或快捷手册进入日常页。只在日常页签、标题及第四档完成标记同时命中后取得完成证明；确认按钮必须与领取标题一起出现。领奖前保存尝试标记，暂停继续先检查后态；未满返回大世界后失败，不写成功记录。

丽都城募从菜单进入，覆盖开启、确认、成长任务及等级回馈。完成判断要求城募画面、已进入等级回馈且领取和确认均不可见；不能把任意空白画面的按钮缺失当成功。领取后重新识别，再进入下一项；不点击购买、升级计划或选择付费奖励。

刮刮卡从六分街 → 报刊亭传送、前移和交互开始，兼容叫醒对话及共享次数提示。每条刮层单独登记投递检查点；暂停后可重新刮同一层，拖动不额外消费次数。只有三层动作完成且刮卡界面退出，或明确收到共享次数已使用提示，才完成返回。菜单、大世界、奖励弹窗和未知画面不能独立证明已刮卡。

所有输入等待可取消，暂停不计入有效超时。原生收尾确认释放后才发布暂停或完成；停止优先于成功。应用组在下一项输入前保存检查点，失败、未保存或未释放输入阻止交接。恢复清单版本单独增加 W 与 Escape，保持已有 v1..v6 语义。

执行包独立于原只读活跃度包，固定节点和资源逐项复验，缺少新包时明确拒绝这三项启动；旧邮件和咖啡资源保持兼容。资源构建和验证不加载或执行参考项目 Python。

## 使用

运行桌面准备脚本会生成资源和匹配的引擎。也可在工程根目录单独生成并离线校验：

```powershell
cargo run -p od-tools --locked -- basic-daily-bundle --reference E:/Code/ZenlessZoneZero-OneDragon
target/debug/zzz-engine.exe basic-daily-bundle-check --bundle resources/generated/basic-daily
```

在“账号与应用组”设置启用项及顺序，按需保存“日常设置”：默认每项超时 120000 ms，范围 1..180000；启动 / 继续延时默认 3000 ms，范围 0..10000。邮件和咖啡继续使用各自参数。进入“一条龙运行”预览保存计划，也可仅本次选择五项中的部分应用、重跑已完成项；“独立应用运行”借用来源组参数，每次执行单项，不触发一条龙结束后动作。计划必须确认账号与真实输入，延时期间切回 1920×1080 游戏前台。

应用组开始前校验所有实际执行项的资源，不能先领取邮件再因缺少后项资源而失败。每次投递前持久保存检查点，保存失败不发输入；后项失败保留前项已保存成功。历史按三个应用分别保存证明，兼容旧记录缺少 `daily` 字段。显示“可试运行”由引擎计划决定，应用目录 `implemented=false` 表示尚未完成正式迁移验收。

当前桌面协议 v33，输入恢复 v7 在既有 Alt、左键、N、F 上增加 Escape 与 W；旧恢复版本仍按原清单释放。日常包共 12 个文件：清单、固定 Pipeline、7 张模板及 3 份 OCR 模型 / 字典。运行资源 schema 3 收录此包，旧 schema 1 / 2 保持原有内容和兼容范围；构建与便携打包都校验新包，详见[资源管理](runtime-resources.md)。

## 来源与验证边界

实现核对参考项目的玩法、画面说明、`screen_info` 和三个应用源码。`resources/daily/source-lock.json` 锁定九份 YAML，校验前仅规范 CRLF 为 LF，避免 Git 换行配置改变语义相同文件的哈希；内容改变仍拒绝生成。模板复用已转换的掩码资源及原始图标，OCR 固定 PPOCRv5 与字典，不引入 Python 运行服务。

执行包的来源锁兼容 `compendium_errands.yml` 已核对的两个版本：参考仓 `b15662f7` 使用 LCS 1.0、黄色绿色通道上限 255；`6ba72c85` 回滚为 LCS 0.5、绿色通道上限 210。两版的区域、文字、识别标记和跳转目标相同。`compatible_sha256` 只登记这份回滚文件的完整哈希，其他变化仍拒绝生成；生成清单移除此兼容列表并记录实际来源哈希。Maa 执行节点继续使用已验证的精确日常文字和 `[200,160,0]` 到 `[255,255,60]` 颜色范围，不随参考仓回滚改变，旧执行包保持兼容。

实际留档的“丽都城募/默认.webp”已选中等级回馈，使用页签文字及黄色 / 绿色颜色联合检查；成长任务使用正文任务标题确认，不能只凭点击坐标判断选中。报刊亭默认截图没有嗷呜标题，入口以返回图标和刮刮卡文字组合确认。以上发现已落实到节点和真实 SDK 固定图回归。

独立测试仓 `basic_daily` 包含状态分支、领取后重新识别、防重复传送 / 前移、参数复制与旧配置默认值、五项同 ID 调度和逐项每日证明、未释放 / 未证明拒绝成功、重算清单后篡改资源拒绝，以及真实 Maa SDK 的已完成活跃度、未知画面超时、暂停与保存失败、城募任务到等级、刮卡三层拖动与返回。`basic-daily.spec.ts` 覆盖表单边界、保存失败重试、三个新独立应用的计划 / 同 ID 控制和选择变化撤销确认。
