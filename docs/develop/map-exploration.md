# 空洞探索

独立应用 `map_exploration`，从当前空洞区域开始，先扫描观测奇点，再扫描小卡格车。无需预录锄大地路线，沿追踪后的小地图绿色引导点移动，遇到战斗时交给当前账号的自动战斗脚本，结束后重新读取导航。

开发版默认使用 [python-scripts/apps/map_exploration.py](../../python-scripts/apps/map_exploration.py) 进行绿点识别、导航选择、进度判断和到点决策。配置与命令见 [Python 开发入口](../../python-scripts/README.md)。Rust 继续执行地图流程、输入、战斗、结果核验与运行记录；脚本返回语义动作，由同帧原生观察验证条件。每帧 JSON 请求与响应保存在 `artifacts/python-dev/<运行 ID>/trace.jsonl`，可直接回放；修改脚本后重新运行应用或暂停后继续即可加载。发布构建保持原生策略。

运行入口与应用组共用预览、冻结战斗设置、运行记录、F9 暂停和 F10 停止。新建应用组默认包含禁用的“空洞探索”；读取已有账号配置时，也会在各组末尾补入缺少的禁用条目。打开“账号与应用组”或“独立应用运行”即可找到，长期启用项和顺序由用户保存。旧配置文件在用户保存设置时才更新。

请先进入需要探索的区域，并在自动战斗页保存完整战斗脚本。应用每轮先重置地图视角，再读取底部滑块并拖到最小缩放，连续确认后按重叠窗口拖动地图，每次拖动后重新截图再识别，最多扫描 49 个窗口。切换区域后可再次运行，应用不自动跨区域传送。

地图图标以用户提供的 2026-10-25 截图为素材，运行时编译进识别器。点击候选后必须回读右侧名称，排除其他图标；已解锁奇点跳过。交互只接受目标名称及解锁、开启等操作提示，完成须有交互后状态或奖励证据。缺少引导线或画面过期时先松键并重新获取导航，转向不收敛、恢复失败或长时间没有进展时停止，不以盲走代替导航。

暂停继续从当前画面重读，丢弃屏幕坐标和引导点。战斗前释放跑图输入，战斗后重新读取小地图；整个应用受累计超时约束。完成须读取区域信息左侧小卡格车计数并确认已收集数等于总数；用户截图中该计数为 09/17，旁边金色方块的 01/02 不作为卡格车完成证据。遍历没有发现目标但计数未满时报告未完成，不能以空画面宣告成功。

沿引导线前进时连续有效帧共用同一控制器并保留 W，小幅纠偏继续前进，大幅转向先松键。交互、战斗确认、引导线丢失、截图过期、暂停、停止和执行失败均释放移动输入。

从探索画面开始时，点击同帧识别到的小地图中心打开区域 3D 地图；退出地图使用 Esc。N 是地区快捷导航入口，不用于本应用的地图打开或关闭。若开始时已在地区快捷导航，先返回探索画面，再打开区域地图。失败、停止及成功的最终记录由分项包装器保存一次，保留具体失败原因。

追踪后出现“已开始追踪，是否传送至附近？”时，仅在识别到该完整提示及对应确认按钮后确认传送；等待新的世界小地图出现，再重置转向状态并读取引导线，传送等待最多 45 秒。新运行若开始于遗留的该弹窗，先取消并重新扫描、核对目标名称，然后重建追踪。

战斗区域内即使敌人已清空也可能没有绿色引导线。此时识别当前小地图中唯一的对应目标图标，在暗色道路和视野光锥校正后的道路上寻找连通路径，给边界留出余量，禁止斜穿拐角；每帧重新计算短路点。仅在目标可见、朝向有效、道路连通且仍有进展时持续移动。引导线恢复后立即切回引导线；连续道路导航最多 60 秒，持续移动 4 秒没有道路进度则松键并尝试恢复追踪。

绿线同时向多个方向延伸时，不任取最近的一颗绿点。当前目标一旦出现这类歧义，后续即使其中一侧暂时消失，也继续忽略该目标的绿线，改用已验证的道路。若道路也无法确认，只有当前小地图中唯一的观测奇点、世界画面中的同心环标记和唯一的 3～35 米距离同时成立时，才按世界标记调整镜头并持续前进；不依赖异常绿线或小地图朝向。每帧核对距离，4 秒未缩短至少 0.5 米、转向 8 次或持续 30 秒后松键并进入有界追踪恢复。新目标重新评估绿线；回归包含真实双向绿线截图、单侧绿线暂时消失、标记缺失、连续前进和距离停滞松键。

无可用引导线或道路路径时先松键，等待 3 秒后重新打开区域地图，优先核对当前详情或唯一的追踪图标；无法确定时重新缩放拖图扫描。核对名称后取消旧追踪并重新追踪，出现附近传送弹窗时选择取消，保留当前位置。每个目标最多重建两次追踪，仍无法取得有效导航时停止。回归包含真实战后截图、拐角、断路、过窄道路、目标缺失和多目标歧义。

到点时引导线和朝向可能已经消失，不再继续按导航丢失处理。世界目标名称或唯一的 3 米内距离标记触发到点阶段：先按同帧目标位置调整镜头，再短按 80 毫秒前进改变人物朝向，最多三次；仅在识别到该目标的 F 提示后交互。F 提示包含右下角原普通攻击槽的圆形按键，除 OCR 外使用固定 UI 字形验证。交互后仍须奖励文字或地图“已解锁”状态确认，不把到达、转向或按下 F 当作完成。

识别诊断会在资源目录的父目录下 `artifacts/map-exploration/<运行 ID>/` 保留最小缩放图和前六个扫描位置的同帧 PNG、识别 JSON；同一位置覆盖更新，便于核对拖图是否生效以及候选为何漏识别。回放测试不写入这些文件。

进入战斗前，先排除同帧地图、追踪弹窗和带小地图及功能菜单的探索 HUD，再连续确认两帧攻击界面；确认期间释放输入。动态小地图匹配命中错误位置时仍回退到固定区域，这条规则同时用于战斗结束后的探索画面确认。

头像尚未识别出来时仍独立读取前台能量和技能按钮，供冻结通用脚本的“未知角色”分支出招。战斗结束动画中玩家箭头暂时不可见时，同时命中的探索菜单和地图按钮可确认返回探索，继续等待新的有效引导线。失败记录保留战斗帧数、过期帧数和动作数。

只读 Maa 识别使用共享资源的专用 Tasker，绑定不支持截图和输入的回调控制器。避免每次模板匹配触发 Win32 `inactive` 的窗口及输入恢复开销；游戏截图、实际按键、暂停、停止、异常收尾和控制器交接仍使用真实控制器。回归包含慢收尾控制器，验证连续识别不调用真实 `inactive`，而最终交接仍松键并执行收尾。

图标及引导线用附带截图回归；Maa 整帧只读检查已命中观测奇点详情、未解锁状态、停止追踪按钮及详情关闭按钮。实际交互提示、解锁后态和完整游戏连续运行仍需实机验收。桌面与引擎使用协议 v47，界面和地图识别资源复用 `generated/world-patrol`，图标素材直接编译进识别器。
